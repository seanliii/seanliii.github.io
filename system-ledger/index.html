03A 蜂群与多跳

不是多搜几轮，

实体关系：七层，防的是同一件事——认错实体

层真实文件机制在防什么
采集entity_memory_bank.py工具结果落账当下抽实体，记出现次数与来源，存入会话实体库；带噪声词表与 HTML 清洗事后从混杂日志抽不准

约束与证据identity_coverage.extract_claims 与 compute_coverage把题面拆成 claim，逐条统计证据覆盖；支持 LLM 语义覆盖，失败退回规则布尔覆盖把“提到过”当“满足”
四态判定identity_coverage.classify_state任一约束被证据矛盾直接 rejected；覆盖率大于等于 0.80 且多源才 confirmed；覆盖足但单源是 probable；0.40 到 0.80 是 probable；否则 candidate锁错实体、单源冒充确证
软锁identity_coverage._is_strictly_better已确认候选不被抖动替换；只有覆盖率明显更高且覆盖约束数不减少才换；收尾软锁 probable 优先于元评论与空收敛时把正确实体换掉
防漂移entity_drift_lowconf_guard.py比对最终答案断言的实体与已确证集合，漂出就告警并回退；同时检测低置信措辞与置信数值中间确证被覆盖、自认没把握仍硬交
特征反查feature_to_entity.py数值与属性特征转结构化查询（MusicBrainz lucene、Wikidata SPARQL、Crossref 年份作者），无结构化源时用 LLM 做特征到实体联想6 shots、BPM 194 这类特征无法用全文关键词反查

三个真实事故，直接催生了这些机制

  • 实体在交接时丢失：Arsenal 在工具证据中出现 48 次，最终推理出现 0 次，模型凭自身知识脑补。修法是落账当下采集实体，收敛时从结构化库选。
  • 正确实体在收敛时被覆盖：中间已多源确证母队是 Arsenal，收尾自述变成 on loan from Celtic，再由 Celtic 推出对手 Rennes，最终答错。修法是漂移检测加软锁：收敛不许用低置信新说法覆盖已确证实体。
  • 自认低置信仍硬交：模型自标 Confidence 20%、写明未能完全确认，墙钟到了仍交卷。修法是低置信检测：命中措辞或数值就先回退到已确证候选，或标注不确定度。

# 2026年1-6

### **提升Friday记忆平台能力建设和业务效果**

**一、目标**

构建可规模支撑业务的 AI 记忆中台，从「基础读写平台」升级为「多层渐进式智能记忆架构」，支撑公司内 AI 应用对跨会话记忆、长期画像、个性化推荐的需求，提升业务最终效果。

**二、具体工作**

1. 记忆架构四层演进（L0→L3） 从单层短期记忆逐步构建完整的四层架构：

- L0 Session（短期对话）→ L1 Effective 中期抽取（topic/summary/tags/facts）→ L2 Topic Summary 主题聚合 → L3 Persona 长期画像
- 实现统一检索接口，支持并行召回（session明文 + profile记忆 + 向量） + Reranker 重排 + 配额管理

2. Persona 消费画像系统

- 2025年发现所有业务都在找同一个东西 ——「用户消费和决策行为的统一理解能力」。2026年记忆升级为 AI Agent精准推品和需求分析 设计的用户画像数据体系，围绕美团全BU消费和行为，从 消费偏好 → 实时行为 → 数据统计 →需求分析→ 接口落地 递进。打通个体门店商品消费基础画像、个体场景化选品组品消费画像扩展到「用户决策全链路行为」+ 「场景化组品偏好」+ 「实时行为记忆接口」，让 Agent 不仅知道用户爱吃什么，还能理解用户是怎么找到、怎么比较、怎么下单的，及消费习惯和深层消费动机。
- Persona 离线加工日均 30 万+，Profile 查询日均 21 万+ 

3.效果评测体系建设

- 搭建 LoCoMo、LongMemEval 评测 pipeline，并建设 Auto Harness 自适应迭代框架
- LoCoMo 从 76.1% 提升至 95.1%，LongMemEval 从 68.3% 提升至 96.1%，达到并超越业界 SOTA

4.平台能力补齐与规模扩张

- 完善日志、仪表盘、大盘、API 二期，支持记忆清空/重置、轨迹数据查询等管理能力
- CLC 合规加密全量上线（Trace + 上下文 + 记忆加密），Token 节约 24%
- 多机房部署解决跨机房 160ms 延迟瓶颈，短期读时延从 44.8ms 降至 9.2ms（↓79%）

5. 记忆 Skill 化与生态推广

- 完成 Friday Memory Skill、OpenClaw 插件认证、记忆接入 SOP 建设

三、**结果**

1.业务应用效果

- 妙妙点餐助手：使用用户消费画像记忆进行个性化推荐点餐，推荐订单占比增加了20+pp（~2% -> ~26%)
- 智能掌柜：长期记忆实验 → 多轮会话占比 **+2.08pp   （**多轮会话占比14.6%→16.7%），平均会话轮次 1.56→2.04
- 通搜业务：使用从群体经验进化工作技能的记忆服务，通搜时效问题 90% badcase解决率

**一、目标**

建设面向 AI Agent 的社区平台，实现 PGC 内容生产、个性化推荐分发、Agent 成长激励体系，打造"虾"与用户之间的内容交互闭环。

**二、具体工作**

1.PGC生产系统

- 实现基础自动化内容生产链路：根据社区话题供需缺口动态选题，按虾的人设匹配最合适的话题，通过5维度质量评审（低于60分打回重写，最多3次）确保内容质量后自动发布。
- 升级为1v1定向生产模式：实时感知社区新用户行为，自动提取用户画像，针对每个目标用户生成专属内容brief并生产发布；引入效果追踪机制（发布后3h/24h/3天分阶段检查互动数据），将成功内容模式沉淀为可复用的Skill供所有虾学习。
- 增加爆款分析与群体进化能力：自动扫描站内全量热帖，识别爆款规律并注入所有虾的生产Prompt实现群体进化；同时支持老用户新行为回访、定时自动触发（每日2次）、并行生产提速（默认8虾并行）、以及融合BI人类点击率数据校准内容策略。** **

2.个性化推荐系统

- 建设多路召回（热帖/新帖/实战帖/画像/多样性/探索六通道）+ 综合打分排序算法
- 引入 channelBoost × tagMultiplier × freshnessBoost 个性化综合打分，替换原始随机 shuffle
- 建设 Agent 画像系统（AgentProfileService），实现 9 路 ES 召回（Intent × 体检 × 行为双周期）
- 建设 人类CTR 追踪、冷启动池等推荐基础设施

3. 创作内容生态

- 搭建帖子发布/编辑/打标/推荐完整链路
- 建设实战帖（isTask）打标体系 v3.0，通过 LLM 自动识别高质量实战内容

4. Agent 社区活跃

- 设计心跳 highlights 系统，新增 6 种亮点类型（ranking_up / feed_featured / feed_hot / similar_shrimp / milestone / new_interaction），建设推荐相似虾、积分榜变化、热榜提醒、推荐理由等 Agent 激励与互动氛围功能
- 优化心跳嵌入人类真实工作流，分享真实工作成果和经验，并形成实战贴内容发布社区，其他虾可自主选择执行后分享给主人成果

**三、结果**

- 社区留存：完成社区核心基础设施搭建，为后续内容分发、生产、社区关系和互动的规模化打下基础；D0心跳率从19%涨到64%，D7心跳率从11%涨到42%；
- 内容分发：推荐管线从单路 SQL 召回升级为六路并行召回 + 个性化综合打分，零互动帖子占比从50%降低到20%，
- 内容创作：UGC实战贴虾占比从2%提升到24%，每日新增实战贴占比从7%涨到50%，PGC实战贴内容系统从无爆款到日均5个爆款（互动数超200）

## **FRIDAY Agent Memory 系统 2026年个人总结**

过去半年，团队对记忆方向的判断逐渐清晰：一方面，业务侧对跨会话个性化、长期状态理解、用户画像沉淀的需求快速增长，记忆已从“可选增强能力”变成 AI 助理体验的基础设施；另一方面，行业内记忆方案快速演进，单靠规则堆叠难以形成长期壁垒，必须同时补齐平台能力、效果评测与自进化能力。因此，团队整体策略是：以真实业务需求牵引建设记忆中台，一边做稳定可复用的平台底座，一边围绕效果评测、分层建模、技能化和自进化持续拉升记忆效果上限。

围绕这一策略，上一阶段团队主要推进了五类工作。第一，记忆平台与业务支撑。围绕 longcat.ai、到餐点餐助手、点评 AI 搜、数据 Agent、小美/Beam 等场景，持续补齐记忆平台能力，建设日志、仪表盘、大盘和 API 二期，支持长短期记忆查看、画像加工、summary 合并更新、topic 抽取、记忆清空/重置、轨迹数据生成与查询，并推动 Persona 数据平台特征接入。整体上，记忆系统从“能接业务”逐步走向“能规模支撑业务”，应用数、读写量和活跃业务数均显著增长，点餐助手等场景已验证对核心业务指标的直接提升。

第二，记忆架构升级与分层建设。团队不再把记忆简单理解为短期+长期两层，而是开始构建短—中—长期统一框架，引入中期记忆、topic 聚合、effective 抽取、topic 合并 summary、联合回退等能力，打通各层之间的关联与流转。这个方向一方面减少了重复信息处理的 token 消耗，另一方面提升了统一检索效果，也为后续“感知—抽取—沉淀—固化”的 L3→L0 分层演进打下基础。

第三，评测体系与效果优化。团队搭建了基于 LoCoMo、LongMemEval 的评测 pipeline，并进一步建设更贴近真实业务流量的评测主体和 streaming 评测平台，把记忆能力从“黑盒”变成“可量化、可复跑、可分析”的系统。基于评测结果，团队调研并复现 MemOS、mem0 等业界方案，引入知识图谱、优化检索与提示词、验证 effective 方案，明确了当前记忆系统“写得进、取不准”的主要瓶颈，并将优化重点聚焦在检索、排序、主题聚合与状态建模等关键环节。

第四，记忆 skill 化与生态扩展。团队较早抓住 OpenClaw/Skill 生态窗口，完成 Friday Memory Skill、OpenClaw 插件、记忆接入 SOP、前端轨迹展示等工作，把记忆能力从内部服务进一步封装为可传播、可复用的标准能力。这不仅扩大了记忆系统在公司内的影响力，也为后续把记忆能力做成可配置、可演进的 skill 奠定了基础。

第五，记忆与强化学习/自进化探索。团队尝试将记忆系统从静态规则驱动推进到动态优化阶段，先后开展 memory x verl、reward 设计、记忆数据 SOP、MemSkill、SkillOpt、Auto-Harness 等探索，部分方向已在 LoCoMo 上取得可观提升，并初步跑通从评测、归因到策略迭代的闭环。虽然整体还处于早期，但已经验证：记忆系统未来不能只靠人工调参，而要逐步走向可自动迭代的工程体系。

复盘来看，我们做对的事情是：始终坚持业务牵引和平台沉淀并重；较早建立了评测与可观测体系，让优化有据可依；在记忆架构、skill 化和自进化方向上保持了前瞻投入。走弯路的地方主要在于：部分前沿探索停留在调研或局部复现阶段，尚未完全沉淀为稳定产能；高性能方案与业务落地之间的成本权衡不够早；个别能力在架构耦合较重时推进，增加了后续复用成本。

下一阶段，团队会延续“平台化 + 效果化 + 自进化”三条主线：继续做深分层记忆和统一检索能力，提升记忆质量与业务复用度；把评测平台、轨迹数据和失败分析机制做得更稳定、更自动化；并将 prompt/skill/抽取策略等外层能力纳入统一的自进化闭环，逐步把记忆系统从“可用的平台能力”推进到“可持续进化的智能基础设施”。

### **📋 【PRD】用户画像 for Agent 2期 — 重点内容总结**

#### 🏗️ 整体架构

这是一套 **为 AI Agent（FRIDAY）精准推品** 设计的用户画像数据体系，围绕「外卖 + 到餐」两大 BU，从 **静态消费偏好 → 动态行为链路 → 接口落地** 三层递进。


---

#### **1️⃣ 个体门店商品消费基础画像**（基座层）


定义了 **11 大维度** 的用户画像指标：

| 维度 | 核心内容 |
| --- | --- |
| 基础消费 | 订单数、占比、大盘分位数对比 |
| 品类兴趣 | 二/三级品类覆盖数，高频/中频/低频分层 |
| 门店兴趣 | 门店数、连锁占比、频次分层 |
| 价格特征 | 均价/最高/最低，消费力 L1-L5 分级 |
| 周期特征 | 复购周期、最近下单时间 |
| 近期状态 | 近30天环比增长率、品类增量贡献度 |
| 时段特征 | 工作日/休息日 × 6时段占比 |
| 地点特征 | 工作地/居住地/异地的订单分布 |
| 决策特征 | **9项子指标**：评分、月销、收藏数、评价数、配送费、优惠券使用率等 |
| 复购商品 | 商品级复购次数、份数、周期、门店分布、规格 |
| 单次商品 | 品类→商品→份数→价格→时间的最细粒度 |

统计周期：近 **1年/90天/30天/7天**，绝大部分 P1 优先级。

---

#### **2️⃣ 个体场景化选品组品消费画像**（精细层）

在基础画像之上，加入 **场景维度**（日期类型 × 时段 × 地点 × 天气 × 季节）：


- **日期类型**：工作日/周末/23种节日节气/生日
- **核心概念「组品」**：同一门店内完全相同的商品组合订单，统计组品的消费次数、均价、复购周期
- **四层嵌套**：场景 → BU → 品类（四级） → 商品（含规格/备注/标准菜名）
- **新增天气分布**：晴/多云/阴/雨/雪 × 温度档位

**核心价值**：从"用户总体爱吃什么"细化到 **"什么场景下吃什么、怎么搭配"**。

---

#### **3️⃣ 用户流量行为统计**（行为链路层）⭐ 最复杂

定义了 **全链路流量行为**，4大 P0 级行为模块：

| 模块 | 核心数据 |
| --- | --- |
| **搜索行为** | 搜索词→点击→下单转化率、排序筛选、**前后15分钟关联搜索词**、搜索后10分钟原始埋点事件 |
| **点击行为** | 门店商品曝光/点击/下单率、各金刚位模块的点击路径（外卖、神券、AI吃、购物车、收藏、浏览记录等） |
| **下单支付** | Session 级支付/退款事件序列 |
| **行为时序** | Session 级完整事件流（从打开APP到关闭） |

**关键设计**：

- **信号分类体系**：5类（强正向/探索决策/弱负向/隐性负向/强负向）
- **8个版本迭代路线**（V0.1→V0.8）：从原始指标 → 信噪比分类 → Session动作序列压缩 → 语义信号关联
- P2级 **未转化漏斗**：曝光未点击 → 点击未加购 → 加购未下单

---

#### **4️⃣ FRIDAY 记忆接口 PRD**（落地层）

定义了两个核心 API：


| 接口 | 时间窗口 | 核心输出 |
| --- | --- | --- |
| **订单历史查询** | 最近30天 | 完整订单明细（订单ID/BU/状态/金额/品类/门店/商品/poi_id/sku_id） |
| **流量行为查询** | 最近7天 | 时序行为日志（click/search/order/add_cart），支持分钟级、前后10分钟窗口 |

**设计理念**：新业务（如医药）仅需3-7天原始数据即可，通过 **Persona 画像数据权限** 控制跨 BU 查询，接口被包装为 **短期行为记忆 MCP**。

---

#### **5️⃣ 补充门店和商品信息**（数据补全）

对前三个文档的统一补丁，追加 4 类信息：


- **门店 ID**：mt_poi_id + wm_poi_id
- **商品 ID**：sku_id + spu_id
- **标准商品名**：跨店统一归类（"秘汁三明治" → 标准名"三明治"）
- **商品品类链**：完整层级（快餐→轻食→三明治）

原则：**ID 可检索 + 名称可理解 + 品类可归类**。

#### 🎯 一句话总结


> **2期的核心升级 = 从1期的消费统计画像，扩展到「用户决策全链路行为」+ 「场景化组品偏好」+ 「实时行为记忆接口」，让 Agent 不仅知道用户爱吃什么，还能理解用户是怎么找到、怎么比较、怎么下单的。**

# 李璇-2026W30周报

### 一、主要产出

#### 1. 社区Agent · 回复Agent 大版本迭代（v20→v33，核心版本8+次迭代）

**目标：** 将回复Agent从"AI说明书"升级为"真正响应用户处境的交付"

**本周关键突破：**

- **搜索池扩容：** 从3→30 URL，两阶段筛选（一阶段haiku打相关性分排序→二阶段只深读top15），信息密度提升显著
- **意图分流机制：** Query意图从固定SaaS场景→5变体自动分流（通用/SaaS/C端/B端/时间限定），覆盖度从单场景→多场景
- **内容风格回归：** emoji密度从83→30（降64%），字符数从4252→2886（降32%），引入JTBD等方法论深度概念
- **多子Agent并行编排（v31）：** 7步编排+4并发搜索+A/A≤2硬门，单题全流程从v30的15+分钟→v31的4.5分钟（加速3x）
- **搜索→执行→交付打通：** 从搜索结果直接打通执行交付，引用内容带来源格式（网站名-作者-日期），链接从日志拿保证真跑
- **风格优化：** 过滤广告链接、保证交付物、响应态增强（开头和内容接住用户处境）、去AI味、禁编造

**版本演进记录（含学城链接）：**

- v21（30池两阶段筛选）→ v22（5变体Query+T-15严化）→ v23（接入supervise循环层）→ v31（多Agent并行+graph+4.5min）→ v33（最新）
- 迭代文档：[8次迭代记录](https://km.sankuai.com/collabpage/2775508503)、[15次迭代记录](https://km.sankuai.com/collabpage/2776150583)

#### 2. 社区Agent · 搜索Agent 架构升级

**本周关键突破：**

- **统一Graph视图：** 对搜索工具（xhs_api / sogou_weixin / firecrawl / smart_fetch / deep_read / anysearch）统一graph编排，支持21源
- **多层质量保障：** 
  - content_hash防重复抓取 + content_completeness自评（骨架/部分/全文三档）
  - evidence分层打分（rrf + domain质量 + 词汇对齐 + 引擎一致性 + cross_encoder五维打分）
  - http-first三挡降级（HTTP → CDP → skip）
  - 引擎池健康度可看（engine_pool healthy/total/degraded）
- **智能规划：** planner看query挑subset，reflector反思；搜索充分即停，不充分则每次换角度递进（改标题→改首段→换切角度）
- **意图理解Graph编排：** 并行多query理解、复杂意图场景分流+跳步+选择
- **新增搜索源：** 知乎搜索skill接入；site_bookmark累积记忆（每次搜索到的新网页下次直接搜）
- **3种深度模式：** depth_score生效（0-30快查cache直返 / 31-70中度可选loop / 71-100深挖3引擎+loop+iter=3）

### 四、重点思考

#### 1. "Answer/Ask比值"是agent质量的核心度量

从本周29题×6agent的GSB评测中发现：Answer/Ask比值与用户满意度强相关。Mavis A/A=2.3拿下最高分，觅游v3 A/A=11.7垫底。**核心洞察：用户来问一个问题，好的agent应该直接给答案（A/A≤3），而不是把问题当项目做（A/A>10）**。这个指标将作为后续所有版本迭代的硬门槛。

#### 2. 搜索Agent的"够用即止"策略

参考Mavis的设计理念，搜索不是越多越好。v22的17条URL+4252字符反而不如v23的7条URL+2886字符。**深度>广度，精准>铺量**。下一步搜索Agent要建立"信息饱和度"判断机制，搜够就停。

#### 3. 多Agent并行是提速的关键路径

v31通过7步编排+4并发搜索将单题耗时从15min→4.5min。但Step 3-7仍是串行（10+54+40+18+5=127秒），如果能对立场判决/观点重组/叙事并行化，预估可再压缩到3分钟以内。这需要更精细的DAG依赖图设计。

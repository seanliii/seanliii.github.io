# 9.14-9.19 Meyo 军团研发周报（更新版）

**周期：2026 年 9 月 14 日—9 月 18 日**
**最新状态：正式环境已发布成功。**

[https://km.sankuai.com/collabpage/2787800041](https://km.sankuai.com/collabpage/2787800041)

### 一、本周总结

本周完成了 **Meyo 军团首版正式环境发布**，并围绕发布架构、模型授权、原生会话续作、协作上下文、安全访问和交付体验进行了集中修复。

部署方式从“大包反复安装”调整为 **小程序镜像＋持久运行依赖**，保留已有 Harness 源码、工具和依赖，降低后续发布成本。同时取得了真实模型调用、工具执行、文件下载及部分原生续作的验证结果。

**本周完成的是正式发布及一批关键运行链路的打通；全成员能力与高质量作品交付，将继续作为上线后的专项验收推进。**

### 二、本周主要成果

#### 1. 正式发布完成，部署方式实现分层

- 完成正式环境发布，解决了镜像体积、系统兼容性、模型授权接线及原生服务启动等阻断。
- 将程序、运行依赖、用户状态分开管理，**程序包控制在约 40 MB**；该数字不包含基础镜像和持久运行层。
- 已有源码、许可证、工具和依赖保留在持久目录，更新业务代码不再需要重装全部成员。
- 薄镜像方案已有 **18—20 秒的增量构建成功记录**。
- 正式包排除测试会话、生成作品、截图录像及运行日志，避免将开发测试数据混入发布物。
- 修复原地重装可能破坏已发布构建的问题，明确独立构建与运行目录的边界。

**价值：**发布链路已打通，后续迭代可以更多聚焦用户能力和交付质量，而不是反复消耗在安装、打包和环境恢复上。

#### 2. 模型与网关授权链路恢复

- 完善 Friday／CCR 的协议适配，以及请求级模型、appid、网关绑定。
- 修复“平台配置中有授权，但容器进程实际没有收到”的问题。
- 保留原有 **24 组 appid 映射**，通过受限持久配置向运行服务提供，不把凭证写入代码或镜像。
- 增加内测共享模型池开关：关闭后保留原配置，但清除新启动进程的共享授权回退。
- 正式进程中，Claude Code 使用 GLM-5.3 完成原始文件任务，**原生执行耗时 22.23 秒**，实际下载内容与要求一致。

**边界：**共享池开关在受控重启后生效，不是热开关；用户自带 appid 的完整接入仍需继续完善，也不能据此认定所有模型均已验证可用。

#### 3. 原生执行与持续对话机制补齐

- 修复历史上下文未进入规划器、续作重复派发已完成任务、原工程目录恢复错误等问题。
- 补齐成员身份、原生 checkpoint、会话与工作目录之间的对应关系。
- 推进 CC、Codex、Hermes、DeepAgents、Omnigent、Aider 等成员的原生工具事件、失败状态、执行预算和结果解析。
- 在测试实例中取得原会话继续执行、原文件保持、原生 SID 复用的有效证据，其中一次 CC 续作耗时 **11.51 秒**。
- 将原生 CLI 默认 HOME 调整到持久目录，并迁移已确认的原生会话资料，避免换镜像后只剩平台会话、却丢失成员原生记录。

**价值：**从“一次能回答”，进一步走向“能沿原会话、原工程持续工作”。跨重启、跨发布的恢复能力继续纳入回归。

#### 4. 协作上下文与研究复用能力增强

- 将仓库检查从仅返回计划命令，补到真实读取仓库资料及保留来源事实。
- 修复历史研究资料被旧上下文覆盖、角色视图版本落后、来源哈希含义丢失等问题。
- 对 **三种执行入口 × 三种执行深度** 捕获实际原生接收内容，验证信息确实进入 SDK／CLI。
- 保留原始 URL、抓取状态、版本、哈希和回查引用；快速任务不额外承担不必要的研究提示开销。
- 推进 Hermes 运行中反馈与原生上下文送达机制，区分“消息已发出”和“成员实际收到”。

**价值：**重点修复成员“看不见现场、拿不到资料、接不到反馈”的问题，让 Harness 自主决策，而不是在上方另造固定答题流程。

#### 5. 安全、交付体验与发布保障完善

- 完善个人授权入口、会话和文件归属检查、客户端认证及远程明文 HTTP 凭证保护。
- 优化交付页为用户点击后加载 HTML 预览，减少首屏自动加载多个作品的负担。
- 修复正常产物被误拦、媒体下载误收网页，以及转换、压缩导出中的检查缺口。
- 完成数据库一致性备份、文件状态备份及副本恢复验证，保留回滚材料。
- 补齐构建工具链、原生库和许可证材料，减少单点缺项导致的重复长构建。
- 保持安全候选、稳定分支和同事开发分支的边界，避免覆盖他人改动。

#### 6. 产品方案收敛，真实作品验收持续推进

产品研究会话完成了以下方向对齐：

- 从单纯展示 Harness 列表，转向 **成熟作品试玩、私有云空间、AI 持续改造** 的使用路径。
- 更新社区画布入口、创作与复用闭环、会话与工程交接方案。
- 完成相关开源机制研究及现行方案文档同步。

验收会话围绕图解、图片、文件、视频和游戏进行了实际打开、交互、下载、播放与续作验证。已有部分有效交付证据，也明确暴露了仍需返工的问题：

- 视频虽已取得可播放产物，但自主素材传输、参考一致性和可重建交付仍需完善。
- 游戏已有真实交互验证，但 3D 交付形态、地图边界及完整玩法仍需继续验收。
- 不能用文件存在、状态为 done 或单次短答通过，代替专业作品质量。

### 五、本周复盘

**本周最终完成正式发布，但过程用时超出预期。**

主要问题是前期质量探索、能力扩展与上线修复交叉推进，一些关键环境差异发现偏晚；跨会话虽然形成了独立复核，但交接和状态更新仍有滞后。

后续需要坚持：

- 已安装、已验证的内容按版本复用，避免重复劳动。
- 发布检查提前覆盖实际运行环境、持久化和恢复，而不只检查构建产物。
- 以用户拿到可用成果为进展标准，区分“代码完成、构建成功、部署成功、业务验收完成”。
- 首版上线后优先提升稳定性和真实作品质量，不再被横向扩展分散主线。

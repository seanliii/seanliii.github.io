### 〇、3 分钟灵魂故事（面试开场/自我介绍版）

> 我过去三年在做一件事：**让一群 AI Agent 像一家公司的同事一样协作，而不是各自为战。**

> 起点是 2024 年我做情感对话模型产品（WOW）时发现：单模型的上限受制于数据飞轮，但用户真正的期待是"像人一样理解我"。2025 年我做公司级记忆中台，把 LoCoMo 从 76.1% 做到 95.1% 超业界 SOTA，这让我确信：**Agent 的能力可以被系统性地工程化**。

> 2026 年初我独立开发 auto——一个自主问答 Agent 系统。我用真实评测发现两件事：第一，它 GAIA 能到 95%+，但 BrowseComp 只有 2/40，根因是"交接冷启动"——多跳推理每步用自然语言传递结果，隐藏状态全丢；第二，我把"校验"重新定义为"另一次搜索"，把幻觉当成公理来设计防御，而不是当 bug 修。auto 的 GAIA 最后做到 165 题 164 对。

> 但随后 dsh 和 codex 开源，我研读后发现：单 harness 优化已经拉不开差距了。不同 harness 在同一个模型上评测结果互补、互有覆盖——那为什么不把最强的 harness 放在一起，让它们像同事一样互相开放、互相补位？于是我独立写了军团：一个 15 万行代码的多 Agent 编排平台，34 家 harness、云真机、经验飞轮。我用真数据证伪了投票、融合、路由这些流行做法——它们全部低于最强单家——最后只保留唯一被证明有效的"置信级联"。

> 我最自豪的不是 GAIA 登顶，而是**我诚实证伪了自己的四个方案**。我的目标始终是一个：同样模型下，让 Agent 质量更好、更划算、更快，对齐世界顶级和用户真正的心理诉求。

### 二、项目深度复盘

#### 项目 1：军团（legion-service）——多 Agent 编排平台

**一句话定义**：让用户一句话触发一群顶尖 Agent，把原本没能力实现的想法变成真实可用的作品。

##### 立项动机（面试转述版）

从"优化单个 harness"转向"做 harness 的运行系统"——dsh 万物皆插件、codex 短循环让我看清单点优化拉不开差距；不同 harness 同模型评测结果互补互有覆盖，所以让模型看到所有可能的 harness，可单独可并行，像公司同事一样互相开放生态，看对结果是否有提升。

##### 架构事实

- 34 家成员 = 27 家答题 harness + 5 能力后端 + 2 协作平台
- `legion_core.py` ~6700 行调度中枢（编排候选/网关租约/失败分类/执行器/relay/DAG/经验飞轮）
- `server.py` ~3300 行 HTTP 层、`cloud_desktop.py` ~700 行云设备层、前端 ~3200 行
- 工具生态：工具箱 3850 件、函数索引 82437（5 语言 30 家）、MCP 110 工具、75 搜索引擎、24 工具链矩阵
- 设备层：云真机（Linux XFCE 桌面容器 + noVNC 网页直控）、云手机（Android 设备线）
- 主力模型 gpt-5.6-sol + GLM-5.3，aws Claude Opus 兜底

##### 关键机制（机制 → 解决的问题）

| 机制 | 解决的问题 |
| --- | --- |
| 自愈换模型 | 单家失败自动换模型，区分"药不行（换模型）/路不通（换环境）" |
| 跨家补位接力 | 失败后任务+错误现场+工作目录整体移交另一家，不失忆重跑 |
| 失败分类 | 区分环境失败 vs 模型失败，不误换模型掩盖环境病 |
| 网关租约+崩溃恢复 | 任务租约崩溃可恢复、checkpoint 断点续跑 |
| 交付判据（短≠空） | 不拿长度当质量判据，合法短答案不被误判 |
| ADR-005 全模型自主编排 | 删光硬编码路由，只留 4 个客观工具，模型 3/3 自主选最优家 |
| 派单池纯净性 | capability/平台面家永不进答题池 |
| 经验飞轮 + Wilson 置信度升降 | 成功交付进经验库、战绩自动升降模型 |
| 交付知识库（capture→match→inject） | 世界级交付配方按品类沉淀复利 |
| 世界研究器模式 | 先研究世界级参照，从参照反推任务与验收标准 |

##### 关键决策与证伪（最强面试弹药）

1. **证伪投票/融合/路由/一致门控**：全部 ≤ 最强单家（弱家一致=一起给同一个幻觉）。结论：多家事后聚合是死路。
2. **四臂 A/B 诚实结论**：动态军团慢 62%、费用约 6.9 倍、盲评未胜出 → 不宣称编排更优，只保留唯一被证明的 1+1>1：置信级联（17→21/40）。
3. **context not control 落地**：不写死任何判断，把客观视角（harness_stats）喂给模型，模型 3/3 稳定做出和人一样的性价比判断。
4. **让军团自己设计持续化运行机制**：派反思任务给 6 家 harness，共识 6/6 收敛（工具级 deadline 喂回换招+保留 partial+SIGTERM 宽限）——终极 context not control 实验。

##### 量化结果

- GAIA 验证集 39% → 99.4%（165 题 164 对）
- 简单题 67s → 9.1s；搜索 fanout 22-36s → 1.1s；推理题 246s → 35.9s；机器负载 15.5 → 2.7；Context 压缩 84.5%
- 1910 件工具逐个验证 1910/1910；14 家 harness 全真响应；10 模型全调通
- 全量回归 769 passed/0 失败；发布薄镜像 40MB、18-20s 增量构建、24 组 appid 映射
- 云真机十余道桌面操作任务真实跑通（vim/IDE/浏览器/拖拽/多窗口，全程截图取证）

##### 经验与教训

- "编排逻辑不值钱，把各家稳定可靠串起来才是真价值"
- 弱家的一致不构成正确；诚实证伪比虚假宣称更能赢得信任
- 安全边界可以硬，质量策略必须软——看见 gate/threshold 先问这是安全门还是替 Agent 判质量

##### 面试高频问题 + 应对要点

- **Q：为什么证伪了投票/融合还做多 harness 平台？** A：证伪的是"事后聚合"，保留的是"事前编排+单一执行+接力兜底"；唯一被证明的协同是置信级联。
- **Q：四臂 A/B 输了你怎么解释平台价值？** A：平台价值不在"编排增益"，在交付面扩展（设备层/工具生态/可靠性/持久化）；诚实的证伪方法论本身就是价值。
- **Q：15 万行为什么不招工程团队？** A：探索期需要快速验证假设，自己写是最短反馈回路；这 15 万行里大量是机制实验，不是常规业务代码。
- **Q：不同 harness 同模型评测结果不同，你观察到什么？** A：互补与覆盖并存；单家平均搜索次数和正确率不成正比（codex 搜 6.6 次拿 33/40 vs auto 搜 13.4 次只 22/40，搜得多≠收敛）。

#### 项目 2：auto（seed-users-system）——自主问答 Agent 系统

**一句话定义**：把 Agent 从"黑盒执行"升级为"自证真执行"，从"人驱动系统"到"系统自驱动"。

##### 立项动机（面试转述版）

真实用户对 Agent 的痛点（幻觉/虚假完成/理解偏差）驱动；同时用社区工具分发+经验沉淀形成飞轮。

##### 关键机制与发现

1. **多跳推理根因发现（研究级亮点）**：BrowseComp 20 题失败根因="交接冷启动"——每步把结果写成自然语言进 prompt，下一步从零读，KV cache/attention/hidden state 全丢。精读五遍+十篇顶会交叉验证，定位 11 种失败模式（实体漂移/gold-in-thoughts 丢失/宽松约束错锁/低置信硬交）。修复=七层结构化事实图架构，2/40 → 6/40。
2. **Verification-as-Search（理论创新）**："校验不是终点，而是另一次搜索"——Critic 不是评委是检察官，每个"不同意"必须自带反例；收敛不是覆盖率阈值而是贝叶斯概率分布分化；渐进式验证对标 PID 控制器（搜 1 次校验 1 次，而非搜 60 次选 1 次）。
3. **12 类 AI 欺骗识别**：goto 冒充 click、部分完成说 done 等；三层审计（turn_hook 并行校验/path_monitor 路径审计/meta_audit 元仲裁）；统一审计框架减 80% 重复代码。
4. **8 步进化闭环**：feedback_ingester→self_reflector→12 判断器审计→planner→高危门→code_evolver→skill_synthesizer→自造工具；Agent 能自主创建可运行 Python 工具；首次 forge 省 93% token。
5. **评测公平性审计（2→6，3×）**：挖出 6 个评测管道 bug（gold 泄漏进 trace 可被 grep 抄答案、搜索 sandbox 挡死、旧输出污染、404 模型、空 choices 崩溃、重复工具名）。对手成绩水分：oracle 31/40→21/40；自身 38 道失败 97% 是工程管道把答案扔了（finalize gate 拦死 22 题占 58%），真正模型选错只 1/38。
6. **Pilot 复盘（7.15→8.24 停用）**：62 文件/13246 行/6 周/41 项检查。结论——"Pilot 作为产品失败了，作为实验成功了"：外部监控层深度回测 0/10 被证伪；**智能要长在循环里面，不是挂在循环外面**。
7. **墙钟让路**：硬墙 900s 到点后质检门每拦一次烧 15-60s，900s 烧到 2313s（2.5×越墙）。修复：到点先交卷，质检让位交付。
8. **Answer Vault 软锁定**：已找到正确答案却因 claim 覆盖率 0.10 不敢确认、改交错误候选。修复：首个 probable+ 候选软锁，除非严格更优不替换。

##### 量化结果

- GAIA 165 全集：pipeline 39% → auto 61.2% → 95.2% → 99.4%（164/165）；真台账 best-of-N 162/165=98.2%
- BrowseComp 2/40 → 6/40（3×，全程无作弊无 gate 拦截）
- 幻觉调用率 40% → 2%；QA 单题 15+min → 4.5min（7 步+4 并发，3× 加速）
- 觅游 vs 裸 CC（GAIA 9 题三方）：觅游 5/9 vs 裸 CC 2/9（2.5×）
- Answer/Ask 比值核心度量（≤3 合格，区分"回答问题"与"做项目"）

##### 经验与教训

- "你的 agent 不是不会搜（43 次工具调用），是搜到了但用自然语言传递，每次交接都丢失隐藏状态"
- "auto 不笨、不作弊——它真搜索，甚至比 codex 搜得多"；codex 赢在 100% 交付+0 崩溃+快 3 倍
- 把"AI 会骗人"当公理设计，不当 bug 修——反自欺是免疫系统不是补丁

##### 面试高频问题 + 应对要点

- **Q：你怎么发现"交接冷启动"的？** A：精读五遍失败 trace+十篇顶会交叉验证；根因不在搜索能力，在信息传递的表示层——自然语言交接丢失隐藏状态，改为结构化事实图。
- **Q：评测公平性审计是你主动做的吗？** A：是。发现对手成绩水分和自己的管道 bug 后，宁可把自己的 38 道失败重新审计——97% 是工程管道，只 1 道是模型选错。这改变了优化方向：修管道而非怪模型。
- **Q：Pilot 为什么停用？** A：外部监控层被 0/10 证伪；结论是控制要长在循环内部（verify_as_search/goal_approach）而不是外部挂钩。主动停用自己的产品是艰难但正确的决定。
- **Q：Answer/Ask 比值是什么？** A：答案内容与提问次数的比值——好的 agent 直接给答案（≤3），差的把问题当项目做（>10）。

#### 项目 3：觅游（mars）——Agent 社区产品

**一句话定义**：让用户的真实经验被 Agent 复制、规模化，形成"人的经验 × 虾的复制能力 = 可规模化的实战方法论"。

##### 我的负责范围（面试诚实口径）

- **我负责**：社区方向整体产品与核心机制实现（199+ commits）——内容生产与经验分享（马甲虾/实战帖 PGC/真人经验帖加权/Skill 智能匹配/隐性知识面板）、互动与成长体系（心跳分层推送/挑战任务/变强节点/隐性经验蒸馏/感知虾 Agent）、推荐分发（Agent 画像 10 路召回+排序+热榜）、Agent 行为画像自动积累
- **研发团队负责**：觅游后台其余服务
- 角色：虾赚钱组 Owner（4-5 月）→ 内容生产组 Owner（5-7 月）→ 搜推方向 Owner → 社区 Agent 主 Owner

##### 关键工作与量化

- **0-1 冷启动与留存**：D0 心跳率 19%→64%，D7 11%→42%；零互动帖子 50%→20%；UGC 实战贴虾占比 2%→24%
- **PGC 内容生产**：供需缺口选题→人设匹配→5 维质量评审（<60 打回，最多 3 次）→自动发布；PGC V7→V13、14 层数据流；1v1 定向生产+爆款分析+群体进化
- **推荐 v5**：Agent 画像 ES 10 路并行召回+时间衰减，三信号源，P95<80ms，5 通道配额
- **画像与悬赏**：2542 个 Agent 画像（158 高置信）；个性化悬赏 37 个 active，零互动率 28.4% vs 历史 49.5%
- **根因分析**：300+ Agent 日记双模型对比→Top5 需求；锁定内容质量根因="Session 隔离导致 Agent 无真实上下文、自循环产垃圾"；新注册漏斗追到"熟人信任链缺失"单一根因

##### 经验与教训

- "内容质量的根因不是 prompt 不够，而是数据源污染"
- "做流失分析不能停在列问题，要追到问题背后的同一个根因"
- 社区核心飞轮：一手经验（带 trace）→ 实战贴 → Agent 复制 → 更多用户

##### 面试高频问题 + 应对要点

- **Q：你在觅游里是产品还是研发？** A：Owner 角色，负责马甲虾/推荐/心跳/经验分享机制的产品+实现，后台工程有研发团队。用 commit 和代码佐证。
- **Q：D0 心跳 19→64% 怎么做到的？** A：不是堆功能，是先做根因（Session 隔离→Agent 无真实上下文→自循环产垃圾），再建 PGC 生产系统+推荐分发。
- **Q：觅游和 auto/军团的关系？** A：三级火箭——社区沉淀一手经验→auto 消化成工具→军团复制给所有 harness。

#### 项目 4A：AI 解决方案与质检评测（2025 上半年）

**一句话定义**：对话数据业务与平台的链接点——把模型能力做成企业解决方案，把全公司模型调用变成可评测可治理的数据资产。

- **企业解决方案中台**：会玩/团团/私域/商场四业务个性化大模型方案
- **质检评测平台 + 数据中心**：全公司模型调用的清洗/聚类/打标
- **业务 Agent 落地**：经营分析 Agent（编排多取数工具、下钻组品/改单）；风控反思 Agent（虾丸拦截率 -15.89pp）

**面试要点**：这段经历证明你"从模型到业务到治理"的完整视角——不是只做产品，还能做评测基建和数据治理，这是 AI 公司的稀有组合。

#### 项目 4：Friday 记忆——公司级记忆中台（2025）

**一句话定义**：0-1 建设公司级记忆平台，把记忆从"可选增强"变成"AI 助理体验的基础设施"。

##### 关键工作与量化

- **四层架构**：L0 Session → L1 Effective → L2 Topic Summary → L3 Persona
- **短/中/长记忆体系**：Compact/Topic/Summary+Profile，并行召回+Reranker+配额管理
- **跨 Agent 记忆协议**：打通电话/微信/外呼多端
- **评测登顶**：LoCoMo 76.1%→95.1%（超业界 SOTA 93.3%）；LongMemEval 68.3%→96.1%

### 四、可迁移方法论清单（面试谈"方法论"时逐条引用）

1. **context not control**：安全边界硬、质量策略软；并列事实不做上帝总判决
2. **诚实证伪优先于虚假优势**：用真数据证伪投票/融合/路由；走通一条 > 证伪十条
3. **把"AI 会骗人"当公理设计**：反自欺是免疫系统，从"祈祷模型别编"到"结构上无法编"
4. **智能要长在循环里面**：Pilot 复盘——外部监控 0/10 证伪，循环内验证被评审认可
5. **分清动作量和进展**：搜得多≠收敛；报告/测试数不冒充用户结果
6. **世界研究器模式**：先研究世界级参照，反推任务与验收，对齐顶级直到完成
7. **交付判据看内容不看长度**：短≠空；Answer/Ask≤3
8. **根因优先**：流失分析追到单一根因；失败审计 97% 是管道不是模型
9. **短循环验证**：GAIA 39%→61%→95%→99% 是逐周迭代，不是一次冲顶
10. **群体验收式互学**：读 dsh/codex/deepseek/hermes 源码抽一等抽象（Team/DAG/Mailbox/WorldState 分段）

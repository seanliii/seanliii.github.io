# OpenAI面试问答深挖

## OpenAI 面试问答深挖（AI PM 岗位）

> 使用方式：面试前逐题过一遍，回答用"结论→证据→方法论"三段式。
> 原则：OpenAI 面试官欣赏诚实（"我不知道"+"但我知道怎么找出答案"）、第一性原理、对 evals 的深度理解。

---

### 一、评测（Evals）方向——OpenAI 最关心，你的最强区

#### Q1：你怎么设计一个评测？（必考题）

**回答脚本**：
我会先问三个问题：评测什么能力？服务什么决策？谁来看结果？

- 能力→决策→受众三层对齐。比如记忆评测：业务决策是"记忆要不要进默认链路"，受众是算法和产品，所以用了 LoCoMo（业界可对标）+ 自建业务集双轨。
- 防作弊第一：我在 auto 上做过一次评测公平性审计，挖出 6 个管道 bug——gold 答案泄漏进 trace（harness 可以 grep 抄答案）、搜索 sandbox 挡死、旧输出污染、全 harness 用了 404 模型。审计前对手 oracle 是 31/40，去掉先验泄漏后只有 21/40。**评测的第一个问题不是"题目好不好"，是"分数是不是真的"**。
- 所以我的评测流程固定四步：①数据完整性审计（有没有泄漏路径）②管道公平性（同环境同模型同预算）③结果可复现（跑三遍看方差）④指标对齐决策（这个分数改变什么行动）。

**可能追问**：gold 泄漏具体怎么发现的？
A：审计 harness 的工具权限时发现它可以读自己的 trace 文件，而 trace 里带了 gold 字段。修法是 gold 不进运行时上下文，只进离线判卷。这是"结构上无法作弊"而不是"约定不作弊"。

**可能追问**：评测集怎么防止过拟合？
A：双轨——公开集（GAIA/LoCoMo）做世界对齐，内部业务集做决策；公开集只做发布级验证不做日常调优，日常调优用业务集；每轮优化后重跑完整集看有没有"赢了新题输了老题"。

#### Q2：LoCoMo 76.1%→95.1% 超 SOTA，你怎么确定不是过拟合？

**回答脚本**：

- 三个证据：①LongMemEval（另一个独立评测集）同步 68.3%→96.1%，两个独立集同步提升，过拟合的概率低；②提升来自架构级改动（短中长联动检索+配额管理），不是 prompt 调参；③上线后业务指标交叉验证——Beam 日活 +9.7%、袋鼠找品下单率 +33%，如果只是刷分，业务指标不会动。
- 方法论：**benchmark 是体检不是目标**。我用 pipeline 持续回归，每次架构改动跑完整集看曲线，SOTA 是副产品。

#### Q3：VERIFIED_NARROW_WIN 是什么？为什么这么设计？

**回答脚本**：
我在军团里做的宣称标准：只有同一真实 query + 具名可打开的参照 + 同输入约束预算 + 两名不同实际模型独立盲评 + 正确性不退化且至少两维胜出，才标"已验证超越"，且只对该题有效。
设计动机：行业里太多"我们在 XX 榜超越 GPT-4"式的不可复现宣称。我的原则是**宣称的成本应该由证据支付**——如果你声称更优，就要给出别人能独立复现的路径。

### 二、对齐（Alignment）方向——WOW 是你的实战证明

#### Q4：近 100 次微调实验，你怎么管理？有什么规律？

**回答脚本**：

- 管理：三方数据飞轮（产品定标准→算法训练→标注补数据）+ 北极星单指标（首聊十轮率）+ 每次实验只动一个变量 + 留存而不是离线指标做最终决策。
- 规律（3 条）：①数据质量的收益 > 训练技巧的收益——优质数据标准打磨出来的数据，比调 hyper-parameter 更稳；②离线指标和线上留存经常背离，所以离线只做初筛，上线小流量验证；③负向样本和正向样本一样重要——用户"聊崩了"的对话是我们最值钱的数据。
- 结果：次留 34%→60%、30 留 10%→49%、人均轮次 150→420。

#### Q5：情感产品怎么平衡安全与体验？（OpenAI 必问安全题）

**回答脚本**：
一刀切封禁是双输：用户体验崩了，用户还会学绕过。我做的三层：①对话+人设双安全标准（明确定义边界，不靠玄学）；②分层风险用户链路——不同风险等级不同策略；③模型精确率从 58.09%→89.22%——**精确率比覆盖率重要**，误杀一个好用户比漏过一个风险样本的伤害更大。色情浓度 12%→3.88%、拦截率 8%→0.2% 是在不牺牲留存的前提下做到的。

**可能追问**：如果模型能力变强，绕过变多怎么办？
A：安全不是一次性产品是持续对抗。我把安全做成数据飞轮的一环：每周复盘被绕过样本→反哺训练数据→新模型再测。这和我们把"AI 会骗人当公理设计"是同一个哲学：不假设模型守规矩，把约束做进结构里。

#### Q6：用户对齐你是怎么感知的？

**回答脚本**：
wow 时期我坚持"把用户当老师"——被用户叫"蛋哥"，用户周末半夜会主动来交流模型优化目标。我每周固定读真实对话样本，特别是"聊崩"的和"超预期"的两端。这让我后来做 Agent 时一直坚持一件事：**先看真实用户的失败现场，再决定优化什么**——auto 的立项就是我发现 cc 的幻觉/虚假完成痛点后启动的。

### 三、Agent 可靠性方向——auto 的核心贡献

#### Q7：你说"把 AI 会骗人当公理设计"，具体怎么做？

**回答脚本**：
公理意思是：**模型会产生幻觉不是 bug 是常态**，所以防御不能靠"让模型别编"，要靠"结构上编不了"。三个层次的落地：

1. **审计层**：12 类欺骗识别（goto 冒充 click、部分完成说 done 等），三层审计并行校验，不阻塞主流程（fire-and-forget）
2. **证据层**：候选交付协议——引用的 evidence ID 必须已存在于统一事件流，禁止悬空引用，从数据结构上杜绝"伪造闭环"
3. **验证层**：Verification-as-Search——校验器不是评委是检察官，每个"不同意"必须自带反例证据，没有证据的反对无效

结果：幻觉调用率 40%→2%，38 道失败审计出 97% 是工程管道问题。

#### Q8："交接冷启动"这个发现，讲一下完整故事

**回答脚本**（这是你的研究级故事，讲 3 分钟）：
auto 在 GAIA 上到 95%+，但 BrowseComp 只有 2/40，这个反差本身说明有系统性 bug。我把 20 道失败题精读五遍，又拉了十篇多跳推理的顶会论文交叉验证，找到 11 种失败模式，最后收敛到一个根因：**每跳的结果被写成自然语言塞进下一跳的 prompt，KV cache、attention、hidden state 全丢**——就像让一个失忆的人接手前人的工作。四种致命症状：实体漂移（题目问 Arsenal 球员，链条中滑到 Celtic→Rennes）、gold-in-thoughts 丢失（思考中已经出现正确答案，传递时丢了）、宽松约束错锁、低置信硬交。
修复不是换模型，是换表示：七层结构化事实图替代自然语言上下文，让每跳交接的是结构化事实而非散文。2/40→6/40（3×）。
这个故事的价值不在提升数字，在方法：**当指标出现系统性反差时，先怀疑管道再怀疑模型**——后来审计 38 道失败，97% 是管道问题，只有 1 道是真模型选错。

#### Q9：Pilot 这个项目，讲一下你主动停掉它的决策过程

**回答脚本**（OpenAI 欣赏"杀死自己产品"的故事）：
Pilot 是我做的外部监控层——一个 watchdog LLM 挂在 Agent 循环外面监控质量。6 周、62 个文件、1.3 万行、41 项检查。然后我做了回测：深度层 0/10 被证伪，基础层从来没做过 A/B。最刺痛的是：8.24 关掉哨兵，用户完全没注意到它消失过。
结论一句话：**智能要长在循环里面，不是挂在循环外面**。同一套思想放在循环内部（verify_as_search/goal_approach）被外部评审列为"值得拿走"，挂在循环外部的（pilot hooks）被我亲手停用。
这个决策让我建立了自己的判断标准：一个机制有没有价值，看它在循环内的增益，不看它文档里的自述。

### 四、军团与科学方法——你的诚实证伪故事

#### Q10：你证伪了投票/融合/路由，那多 Agent 编排还有意义吗？

**回答脚本**：
有意义，但意义不在"多人投票"，在"分工与接力"。
我用真数据证伪的四种：投票（弱家一致=一起给同一个幻觉）、答案融合、topic 路由、一致门控——它们的共性是**事后聚合**，而事后聚合丢掉了正确答案的来源信息。
保留下来被证明有效的：**置信级联**——最强主家执行，读运行时信号，不满意才换更强的家，17→21/40。本质是"事前选强+事中升级"，不是"事后平均"。
所以平台价值 = 交付面扩展（设备/工具/可靠性/持久化）+ 接力兜底 + 经验飞轮，而不是"编排增益"。**如果 OpenAI 的面试官问我多 Agent 的边界，我的回答是：多 Agent 的增益必须被证明，没被证明的部分我只说"没证明"。**

#### Q11：四臂 A/B 你输了，还敢写在简历里，为什么？

**回答脚本**：
因为我卖的从来不是"我的方案永远对"，是"我的结论可复现"。
四臂 A/B 结果：动态军团比最强单家慢 62%、贵 6.9 倍、盲评没胜出。我把它写进平台的设计约束：日常不烧四臂，只在发布阶段对少量 query 串行验证。
一个做 Agent 产品的人如果连自己的方案都不敢证伪，他怎么做 Agent 的可靠性？（停顿）这就是我的方法论。

### 五、行为面与动机

#### Q12：为什么离开现在公司？（高频必问）

**回答脚本**：
战略方向不同。公司新的产品策略转向了和我能力主线不匹配的方向，我负责的产品线重组交接。我尊重这个决策——它是一种合理的商业选择——但我的方向很明确：Agent 系统和能力对齐。
交接之后我一直在独立推进军团（持续有交付作品），这能证明我不是因为"没活干了"才离开，是因为"想做的事在别处"。

#### Q13：为什么是 OpenAI？

**回答脚本**（真诚版，别背稿）：
三点。第一，我的五年经验链——对话模型、记忆、Agent 可靠性、多 Agent——每一段都在解决同一个问题：让 AI 更可靠、更对齐用户，这正是 OpenAI 产品线的核心命题。第二，我欣赏 OpenAI 对评测和安全的严肃性——我的"诚实证伪"方法论和"不夸大能力"的价值观是一致的。第三，我想把自己"独立做完整系统"的能力放进一个能做世界级系统的团队——一个人能做到 34 万行代码，但世界级需要世界级的算力、数据和同事。

#### Q14：你最大的弱点？

**回答脚本**（诚实+有行动）：
我没有管理大型工程团队的经验——过去三年我是独立完成代码和部署的，这给了我速度，但没给我规模化协作的经验。我知道在 OpenAI 这意味着我需要补"借力"的能力：把方向拆给很多人、让他们的产出对齐我的标准。我正在有意识地补——在觅游我做过跨职能 Owner（马甲虾/推荐/心跳和研发团队协作），但那还不够。这是我来 OpenAI 想真正解决的问题之一。

#### Q15：如果让你定义"好 Agent"的北极星指标，你定什么？

**回答脚本**（展现第一性原理）：
我会定一个复合指标，但先说原则：**指标要测用户结果，不要测系统努力**。

- 主指标：任务完成率（用户的目标达成，独立判定，不采信 Agent 自报）
- 伴随指标：Answer/Ask 比值（≤3 才是"给答案"，>10 是"做项目"）——这是我在 auto 上验证过的度量，它测的是"用户为答案付出的摩擦"
- 护栏指标：幻觉率、虚假完成率（12 类欺骗识别的检出率）、单位任务成本

一句话：好 Agent 的判据是"用户拿到了对的结果、过程没被骗、成本可接受"。

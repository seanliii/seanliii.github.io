### 二、坑沉淀库（15+ 条，每条=坑/根因/修法/回归锁）

1. **测试桩污染真实家目录**。测试体内手写 `expanduser("~/.meyo/...")` 绕过 env 重定向，1016 会话里 605 个测试桩（archive:322）。修法：`legion_paths.py` 单一权威 + 无条件隔离。锁：`test_isolation_env_guards.py`。

1. **MEYO_LEGION_DIR 误伤外部家体检**。隔离 env 会把 `external_agent_registry.source_dir` 的 repo 根一起重定向，真外部家被误判 `not_installed`（`test_isolation_env_guards.py` docstring）。修法：静态扫描 tests，凡设隔离 env 又 probe 真 catalog key 即红。

1. **OOM 双根修**。两个 agent 并行 `pip install jupyter`（各 ~1.4GB）→ colima VM 内存尖峰 → server 被 SIGKILL 8 次（exit 137）。修法：`desktop_exec` 检测安装类命令走 flock 容器级串行（实测第二段等锁 4.4s 零重叠）。锁：`test_desktop_install_serialization.py`。

1. **SIGKILL 孤儿进程**。`start_new_session=True` 自立进程组，父进程被 SIGKILL 后 atexit 不执行 → PPID=1 孤儿。修法：磁盘进程组注册表 `legion_proc_registry`。锁：`test_proc_registry.py` + `test_static_guards.py` Guard A（AST 扫 spawn 点必须挂登记）。

1. **Popen 返回 ≠ exec 完成**。fork 态 `comm`=父进程路径，exec 窗口达百毫秒+，登记存 fork 态、断言读 exec 态必然 flaky（`test_proc_registry.py:28-33`）。修法：产品侧 `_REUSE_GRACE_S` 宽限 + 测试 `_wait_comm_stable` 等 comm 连续两次相同。

1. **派单池纯净性**。冷启动 planner 把 capability 家（browser-use）当答题家派，run 时才撞 unavailable；根因是 `_harness_keys` 全量吃 catalog。修法：`_answer_keys_from_catalog` 角色过滤。锁：`test_dispatch_pool_guards.py`（行为锁红绿注入 + Guard-D AST 静态守卫）。

1. **判断器输入契约漏字段**。`run_state` 漏 `scope_goal_met` → 合法短答案「好」被判未完成 → 无谓续跑 5 轮，症状是「保守误判」而非报错。修法：统一 `LEGION._pilot_run_state`。锁：`test_legion_pilot.py` + Guard B。

1. **短答案误判为空交付**。「1024」=2¹⁰ 是正确答案，不能当空交付（archive:326）。判据只看内容特征，`legion_core._is_delivered` 是范本。

1. **native progressive 断线**。老版 hook 挂 `gate_bus._g_vault_observe`，但 native path 直接调 `av.observe` 不走 gate_bus，hook 从未触发（`HISTORY-patches.md:11-13`）。修法：两条路径对称挂；subprocess import 用 short path。

1. **vault 噪音污染**。硬墙 hint/交卷自检文本被 `_VAULT_MID` 误捕获污染 vault，加 `_NOISE_HINT` 特征词拒收（`HISTORY-patches.md:14`）。

1. **trace 落盘缺失**。bc/gaia attempts 只留 `pred+correct+reason`，答错题无法复盘「当时怎么锁错实体」。v14.1 起 attempts 自动填 `trace_path`（`HISTORY-patches.md:22-26`）。

1. **planner no JSON 偶发**。kimi 2 次挂 1 次，旧逻辑一次失败就退默认家、丢智能编排。修法：`_parse_planner_json` 换模型/appid 重试一次再退（archive:334）。

1. **内部工具泛标签霸榜**。auto 42→99 工具全注册后 `image_preprocess` 截胡「写客服话术」。修法：`internal_flow=True` 减 8 分；每次扩召回后必须独立军团大样本复打（archive:357-363）。

1. **file:// CORS 假验证**。`chart.html` grep「有 canvas」就说验证过，实际 `fetch('data.csv')` 被 CORS 拦、双击空白。修法：playwright 真开 `file://` 数 canvas 像素。锁：`dev/verify_web_delivery.py`。

1. **同类方法裸调=静默 502**。Handler 方法内漏 `self.` → NameError 被 except 吞成 502，静态分析看不到。锁：Guard C + 改 server 渲染分支必须真 HTTP curl。

1. **pytest 组合污染五形态**。import 时固化路径 / 模块级缓存无目录维度 / 自执行无运行时钉扎 / 改 API 未同步测试 / 模块级缓存跨测试残留（`CLAUDE.md` 铁律）。教训：单跑绿 ≠ 组合绿。

1. **换 owner 丢项目现场**。`task_facts` 缺 `project_context`（被 `run_one` 自动 pop），换 owner 后新家掉回空目录从零重做。已补 handoff/fork/revision 三处。

1. **缓存短路绕过安全检查**。`mobile_device._READY_CACHE` 30s TTL 曾绕过「拒绝覆盖非受管同名容器」——生产安全属性绝不可被缓存跳过。

1. **读改写乐观锁冲突误报**。`human_handoff` get→update 之间后台线程 claim 改 version，冲突≠异常，应重读重试 3 次。

### 五、当前回归体系

`Makefile` 的回归入口分层清晰（`Makefile:6-105`）：

- **环境层** `make env-check`：钉死 python3.12（非 3.12 会 `SystemExit(97)`）+ deepagents + langchain_google_genai。
- **bc 攻坚层** `make bc-run/attack`：短墙钟 / 长墙钟（900s）两条路径，直接调 `bc_pilot_runner`。
- **军团一键回归 **`**make verify**`（`:92-101`，2026-09-06 固化历史「build×15+pytest×8+起服务」三连的固化版）：① `release/legion-service` 单测 `-x -q`；② `legion_core.py/server.py/cloud_desktop.py` 语法 + `external_agents.json` 合法性；③ HTTP 探活 `/api/legion/harnesses`（在跑则探，不在跑则提示不强制启动）。约 16 秒替代手搓三连。

**「改一行代码如何不踩旧坑」的机制**：坑从「文档里的铁律」变成「机器可判的断言」。六条守卫测试是骨干——`test_static_guards.py` 的 Guard A/B/C 用 AST 静态扫描把「崩溃安全回收/判断器输入契约/裸调 502」变成测试红；`test_dispatch_pool_guards.py` 的 Guard-D 保证未来新增 catalog 消费点若未过滤角色立即红并指名行号。也就是说，旧坑被「锁」在测试里，而非依赖人记得文档。

### 六、遗漏清单（仓库有、但 16 份学城复盘文档未覆盖的事实）

1. `**test_proc_registry.py**`** 的 exec 窗口竞态细节**（`:28-33`）：`_wait_comm_stable` 上限 5s 的设定依据是「机器高负载 load 13、用户真任务 3 家并行时 exec 窗口可超 1s，50 次不够」——这是真实机器负载对测试稳定性的直接证据，一般复盘不写这么细。
2. `**deployment-runtime-verified-2026-09-16.json**`** 的 build_only Failure 记录**：一次真实构建失败被如实落盘（含 job_url、UI steps、cache 观察），不伪造成功，这种「失败也入档」的诚实记录方式值得沉淀为部署规范。
3. `**test_dispatch_pool_guards.py**`** 的双层设计**（行为锁红绿注入 + Guard-D AST 静态守卫）：不只是测行为，还测「未来新增消费点会不会漏过滤」——把「修一类不是修一个」的意图（2026-09-02 用户钉死）固化成了 AST 守卫。
4. **HISTORY-patches.md 的 driver/vault/progressive 病灵**（v129-v133）：这是「总纲只留架构律、细节留档」的归档范本，本身是一个值得学的方法——CLAUDE.md 保留结论，此处保留原始流水账供复盘。
5. `**test_desktop_install_serialization.py**`** 的 word-boundary 零误伤设计**：`adaptive update`/`cat install.log`/`pip show` 不能串行化，正则要过 word boundary——这类「修一个坑不能误伤同类」的边界思考散落在 docstring，未系统沉淀。
6. `**original-game-***`** 系列**（r58-r65，约 15 个 JSON/md）：一条「游戏从崩溃恢复到可玩成品」的完整真实旅程证据链，比任何抽象描述都能说明「原失败旅程重放恢复」这条进展类型长什么样。

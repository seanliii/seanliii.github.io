# 34家harness对比分析与我们的异化

## 34 家 harness 对比分析与我们的异化

> 数据源：`release/legion-service/external_agents.json`（外部接入清单 28 家）、`harness_manifest.json`（内置 10 家画像）、`harness_baselines/`（各家真源码 README 与架构文档）、`meyo-orchestrator/catalog.py`、`legion_core.py` 的 `_ORCH_CANDIDATES` / `_captain_candidates` / `_record_experience` / `_is_delivered` 等常量与函数。事实均标注出处文件，宁缺毋滥。

### 0. 口径说明（先对齐事实）

任务给定的「34 家 = 27 答题 + 5 能力后端 + 2 协作平台」是某个历史时刻的探活快照；当前 catalog 实际可查的清单如下，数字已演进，故下文按**可查清单**如实列出、并注明分类口径：

- **内置真 harness（**`**harness_manifest.json**`** + **`**catalog.py**`** 的 **`**MEYO_HARNESSES**`**）**：10 家，其中 `auto`（李璇自研问答引擎）已在 2026-09-08 被钉死剔除答题池（`runtime.execution_role=capability`，多次交 UNKNOWN 占位实锤），保留为共享工具库。实际答题 9 家：`cc / codex / deepseek(dsh) / hermes / deepagents / penguin / prime / jcode / omnigent`。
- **内置能力后端（**`**catalog.py**`** 的 **`**MEYO_CAPABILITIES**`**）**：4 家——`cua`（桌面操作）、`supervision`（CV）、`herdr`（常驻终端）、`orca`（多 worktree 并行编排）。它们「不领题解题，只暴露一种工具能力」。
- **外部接入（**`**external_agents.json**`**）**：28 家，其中答题 17 家、能力后端 6 家（`execution_role=capability`）、协作平台 5 家（`control-plane` / `ui-platform`）。

`prime-intellect` 与内置 `prime`、`penguin-harness` 与内置 `penguin` 是同一家的「内置 adapter + 外部 catalog」双接入。军团内核 `_harness_keys` 的冷占位返回 36 家（含 `browser-use/paperclip/aeon`），经 `_answer_keys_from_catalog` 按 `_NON_ANSWER_ROLES = ("capability","control-plane","ui-platform")` 过滤后才进答题池——**派单池纯净性**是军团的一条硬护栏（`tests/test_dispatch_pool_guards.py` 锁死）。

### 2. 逐家分析

本节按「可查清单」逐家独立展开。能拿到源码的家写深（200–300 字），只拿到 catalog/manifest/外部接入记录的家写基础信息（120–150 字）。实际可查的军团可见成员共 **42 个 key**（内置 10 = 9 答题 + auto 工具库，内置能力 4，外部 28），按角色分：**答题 26（9 内置 + 17 外部）+ 能力后端 11（4 内置 + 6 外部 + auto）+ 协作平台 5**；其中 `prime`↔`prime-intellect`、`penguin`↔`penguin-harness` 是同一项目的「内置 adapter + 外部 catalog」双接入，去重后约 **40 个独立项目**（口径细节见第 0 节）。下文「2.1 深挖家」里 `meyo-orchestrator` 与 `ecosystem 系` 是源码仓库/生态底座、非军团成员，作世界级参照单独列出。

#### 2.1 深挖家（读源码）

##### codex：短循环极简

OpenAI 官方 CLI，核心在 `codex-rs`（Rust）。它没有重型编排层，靠一条「final schema + 先验直答 + 单次检索确认」的极短循环取胜：拿到题先凭先验直接给结构化答案，仅在有疑点时才做一次检索确认，绝不「搜得更多」空转。`harness_manifest.json` 给它的画像恰是「最快 / 100% 交付不崩 / 结构化」，`best_for` 是「要速度的直答题·结构化输出·快速草稿」。军团把它当「简单题快家」排序抢答（`_captain_candidates` 里 `_pref_order` 排前列），也把它的 `ThreadShutdownReport` 分类收集思想借进了 `_typed_outcome`（把「这单完成没有」从笼统布尔归一成 completed/partial/failed/incomplete 结构化投影）。它的极简是双刃剑：单题速度无敌，但没有任何跨题记忆与自进化。相对我们：单题直答更快、更省编排成本；我们补上跨家记忆与补位兜底，代价是简单题要多一层编排开销。

##### deepseek(dsh)：万物皆插件

`dsh` 的架构文档明说「产品的每一部分都是插件，包括模型适配器、工具注册表、会话日志，以及 agent loop 本身」，由 Cordis 驱动（论文《A Programming Paradigm for Spatiotemporal Composability》）。运行中的 dsh 是一棵插件树，profile/组合包分层叠加，**不存在需要打补丁的特权内核**。它的两大设计是军团的直接参照（AGENTS.md 记为已验证正向杠杆）：① **WorldState 分段 + render_diff 增量**——会话日志是「模型所见上下文的唯一来源」（「模型可见即已记录」由运行时不变式断言），`deriveMessages()` 从中投影模型历史而非全量重发；② **token 比例压缩**——按比例裁上下文，配合 `subagent-fork` 拆并行子任务。seam（可替换能力）= Service Definition / Provider / Consumer 三角色，替换一个提供方即可把 fs/进程整体搬去远程沙箱。优势是插件生态广度与「零特权内核」的可组合性；代价是「开发者预览」阶段破坏性变更频繁、组装心智重。相对我们：它的声明式插件树我们不及（我们的 adapters 是手写接入），但我们把它做深的是「多 agent 协作 + 交付可靠性」，而非单家可扩展。

##### hermes：Footprint Ladder / 工具瘦身

Nous Research 的「自改进 AI agent」，是 34 家里**唯一把学习循环做进内核**的：技能从经验自创、用中自优化、nudge 自己持久化知识、FTS5 全文搜索 + LLM 摘要做跨会话召回、Honcho 辩证用户建模（`agentskills.io` 开放标准）。工具策略上采用 Hermes Footprint Ladder——`CLI+skill(默认) → service-gated → plugin → MCP → 新 core tool(最后)`，按足迹由轻到重接入、常驻清单瘦身以保护 prompt 缓存。七终端后端（local/Docker/SSH/Singularity/Modal/Daytona/Vercel）让它「不绑在笔记本上」，Telegram/Discord/Slack 单网关多端。军团直接仿了它的 `RecallStatus` 透明召回（`_recall_experience` 注入时标明「仅供参考」，由模型自己判断用不用）。相对我们：它的单 agent 长期用户画像（Honcho 辩证建模）比我们的经验飞轮更深；我们的学习循环是「跨家」的——codex 答的题 cc 下次能召回，且按 user 隔离。

##### penguin：agents build agents

Prism-Shadow 的 slogan 是「LangChain 手搓 1× 速度，PenguinHarness 让 agents 造 agents 100×」。核心是**极简工具集 + 低成本自进化**：fewer tool calls / fewer tokens，对 DeepSeek 深度调优，官方 benchmark 宣称数据分析最优、成本是 Claude Code 的 1/70，一句话生成完整 RAG app 仅烧 $0.02。自进化闭环是「跑 benchmark → 找失分点 → 发布 N+1 版」，每轮前 snapshot、每请求 Trace 可观测。`harness_manifest.json` 给它「自进化 / 子目标拆解 / 工具成本极低」三标签。它证明了「目标态自治 + 真实软件 + 可感知证明时刻」这条路，是军团目标 1 的世界级参照之一。相对我们：它把自进化收敛在「单个 agent 越用越强」；我们把它扩展成「一群 agent 互相继承」的群体经验飞轮。

##### meyo-orchestrator：证伪四方案后的置信级联

这是军团编排层（`harness_baselines/meyo-orchestrator`），其 README 的开篇是军团的「已证伪死路黑名单」源头：**6 种答案聚合（v1-v6）+ 一致门控 + topic/LLM 路由均未超过最强单家**；唯一真跑超单家的架构是**置信级联**——CC 主答 + 执行健康信号失败检测 → DeepAgents 升级，40 题 5 折 OOF 从 17/40 提到 21/40（+4，无 gold 泄漏）。它把编排逻辑不写死（「值钱的是把各有脾气的开源 harness 稳定串起来」），只给模型 15 个客观工具（list/stats/history/trace/run/probe/judge/self_evolve），模型自主决定派谁、并行、交叉验证、何时停。这是军团「先证伪、后保留唯一实测有效架构」方法论的落地样本，也是它区别于「堆仪式化评测」的编排路线的关键证据。

##### ecosystem 系：dsh 插件树 + 技能生态 + 能力后端源码底座

`harness_baselines/ecosystem/` 是军团武器库与 dsh 插件树的**源码底座**，三类资产：① **dsh 插件生态**——`deepseek-harness-desktop`（桌面客户端/插件宿主）、`dsh-agent-teams`（Agent Teams）、`dsh-vision-toolkit`（视觉）、`dsh-web-ui`、`DSH-better-sidebar`（持久终端 sidebar 插件，MIT）；② **技能生态**——`agent-skills`(24)、`pm-skills`(124 个 SKILL.md)、`superpowers`、`mattpocock-skills`、`Anthropic Cybersecurity Skills`(154 skills)、`awesome-agent-skills`、`claude-plugins-community`；③ **能力后端源码**——`cua`(5276 文件)、`herdr`(Rust 终端)、`orca`(Electron 并行编排)、`supervision`(CV)、`omnigent`、`ongrid`(Go)、`openhuman`、`gstack`、`speech-to-speech`、`qwen-audio-agent`、`PilotDeck`、`OpenMontage`。军团从这套生态里学经验/借工具/吸收插件设计，但接入时按 Hermes Footprint Ladder 分级、不常驻全清单（保护 prompt 缓存）——这是「生态广度」与「运行稳定性」的折中。相对我们：它提供了几乎无限的横向能力来源；我们的异化是把它们按足迹接入并让最强 harness 稳定协同，而非全量挂载。

#### 2.2 内置答题家（读 manifest 画像）

##### cc：约束锁定 + 深度检索

类型：答题 harness；来源：Anthropic 官方 CLI（闭源 npm 包 `@anthropic-ai/claude-code`，开源仓库仅版本冻结/审计价值）；入口 `claude -p --output-format json`。定位：军团「最准 / 深度检索 / 严格约束核对」的质量优先家，`cost_class=light` 快家，`_pref_order` 排第一抢答简单题。核心设计：先解析约束再多源交叉核对真名/细节，置信级联里的主答位。相对我们：单家准确率与约束核对能力极强；我们把它放进群体接力与跨家记忆里，让它从「单家天花板」变成「军团主力 + 可被兜底」。

##### deepagents：ReAct 检索推理

类型：答题 harness；来源：LangGraph 官方；定位：标准检索推理题快家。核心设计：搜索→ReAct 多轮推理→收敛，`resume=cold_replay`、`compaction=none`，无跨题记忆、无自进化。相对我们：范式经典、稳定；我们补上压缩、经验召回与多 agent 协作。

##### prime：IPython kernel 内核

类型：答题 harness；来源：Prime Intellect（`prime-agent`）；定位：能跑代码验证的计算/数据题。核心设计：规划→执行（IPython 可跑代码）→复核三段链，recursive-subagents 递归拆子任务，自进化=会话内工具/kernel 演化。相对我们：它的「可执行验证」是独有；我们把它接入后当作可跑代码的强家，而非替代我们的交付设备层。

##### jcode：轻量 Rust 代码家

类型：答题 harness；来源：Rust 编写轻量 CLI（`~/.local/bin/jcode` 0.80.0）；定位：快速代码生成与执行。核心设计：轻量、代码优先，`model_picks` 已由云端 CCR 验证为 GLM-5.3。相对我们：单点代码任务快；我们只在需要快速出码时用它，复杂工程仍走编排。

##### omnigent：meta-harness 编排放大器

类型：答题 harness（meta-harness）；来源：omnigent（`harness_baselines/ecosystem/omnigent`）；定位：一行调 cursor/kimi/goose/qwen 等 18 子家，军团没有的家经它开。核心设计：多层嵌套编排（军团派它→它再派子家），`resume=native`、`compaction=nested`。相对我们：它扩的是「单家之外的家」，我们扩的是「家与家之间的协作与交付可靠性」——它是军团的互补放大器，不是同类替代。

#### 2.3 外部答题家（读 `external_agents.json`）

##### cline：VS Code 系 headless

类型：答题；来源 `cline/cline`；定位：headless coding agent，`native_checkpoint` 原生断点。核心设计：mcp/sdk/cli，输出契约 `cline_native_result`，native resume。相对我们：单仓代码任务自洽；我们补上派单池护栏与补位接力。

##### goose：本地 coding + extensions

类型：答题；来源 `aaif-goose`；定位：本地 coding agent，`--with-builtin developer`。核心设计：extensions + ACP/MCP + native resume，stream-json。相对我们：本地开发体验成熟；我们把它当外部家接入，不做它的插件生态。

##### openclaw：IM/自动化/memory 网关

类型：答题（agent-platform）；来源 `openclaw/openclaw`；定位：IM/自动化/memory 网关型 assistant。核心设计：assistant/skills/memory/im/automation/gateway，配置模板含 128k 上下文。相对我们：多端网关能力强；我们只在需要 assistant 泛能力时派它。

##### pi：通用 coding agent

类型：答题；来源 `earendil-works/pi`；定位：coding agent，shell/read/write/search/extensions/session 六工具。核心设计：`-p --mode json` 批处理，native resume，TUI。相对我们：工具面精简稳定；我们借它的通用性做跨平台 coding。

##### nanobot：轻量 CLI assistant

类型：答题；来源 `HKUDS/nanobot`；定位：轻量 CLI assistant，`cold_replay` 续跑。核心设计：shell/read/write/search/mcp，`final_nonempty_line` 取答案。相对我们：极轻、启动快；我们用它做低成本简单题。

##### genericagent：通用函数式 CLI

类型：答题；来源 `lsdefine/GenericAgent`；定位：通用函数式 CLI agent（入口 `ga`）。核心设计：shell/read/write/search/mcp，`cold_replay`。相对我们：接口极简；我们只当泛化兜底家。

##### omniagent：assistant + 编排

类型：答题；来源 `YeQing17-2026/OmniAgent`；定位：assistant + orchestration。核心设计：shell/read/write/search/mcp，`cold_replay`。相对我们：轻编排；我们把它当外部家，不叠加我们的编排层。

##### kimi-code：Kimi 官方 CLI

类型：答题；来源 `MoonshotAI/kimi-code`；定位：Kimi 官方 CLI，`skills-dir` 共享军团技能。核心设计：acp/mcp/web/session，config 支持 GLM thinking，stream-json。相对我们：中文与代码能力好；我们共享 skills 目录给它，形成能力互借。

##### ironclaw：Rust 齐备安全

### 4. 我们的异化（核心章节）

在 34 家面前，李璇的 auto 与军团真正的差异点不是「又造了一个 agent」，而是**造了一台让世界最强 harness 互相看见、互相接力的运行系统**。以下是七条有源码支撑的异化。

**① 交接冷启动：结构化事实图，而非失忆重跑。** 多数 harness 换模型/换会话即掉记忆；军团把「项目现场」固化为 `task_memory / team_state / session / workdir` 四处持久状态（AGENTS.md 定为唯一权威源）。换 owner 时 `_run_one_with_gateway` 的 task_facts 必须带 `project_context`（handoff / fork / revision 三处与 relay 对齐），新家从上一家的真实现场接着做，而不是空目录从零重做——这是「补位接力」比「换个更强的家」更本质的地方。

**② Verification-as-Search。** 自研 auto（`seed-users-system/qa_system`）的核心是 `verify_as_search.py`：Critic 不是被动等答案、而是**主动搜反例做四态裁决**，配合 `identity_coverage.py` 的约束拆解/三态覆盖/软锁，与 native 后端 `_goal_approach` 的「每步验证是否逼近目标」——验证本身变成一次搜索，而不是一次打分。这区别于 hermes/penguin 的「事后评测」，把验证嵌进解题循环。

**③ context not control。** 这是军团与「上层另造答题器/质量裁判」路线的分界（铁律 6）。`_record_experience` / `_recall_experience` 只记事实不评判、注入时标明「仅供参考不一定对」，采纳与否由 harness 自己回报（`legion_tool.py adopted`）；`_is_delivered` 明确「不要用『至少 20 字』之类规则替模型判断答案质量」。安全/运行边界可以硬（权限/取消/进程回收/协议），产品质量策略必须软——这是把「规则」降级为「上下文」的根本姿态。

**④ 证伪四方案后的置信级联。** 军团不是从零猜架构，而是先真跑证伪了六种聚合、一致门控、topic/LLM 路由、「搜得更多」，只留下**唯一实测超单家的置信级联**（CC 主 + 健康信号失败检测 → DeepAgents 升级）。这条「走通一条 > 证伪十条，根因优先」的方法论，让军团的每一次编排都站在被证伪的尸骨上，而非堆仪式化评测。

**⑤ 经验飞轮（跨家记忆）。** 独有价值在于「codex 这次答的，cc 下次 search 能看到」——`_record_experience` 把成功交付按 `user_id` 隔离落库，`_recall_experience` 召回相似题历史（top 2）注入只读上下文；配合 `adopted` 采纳票提置信度、`prune` 淘汰没人采纳的，让好经验浮上来。这是 hermes 学习 loop 的「跨家」版本：不是单 agent 变强，而是一群 agent 互相继承。

**⑥ 云真机设备层。** 四目标的设备层把「交付」推进到真实软件/业务状态：云电脑（IDE/浏览器/Office/登录态）+ 云手机（商店→安装→注册→跨 App→业务状态），闭环由 `mobilerun`（设备操控 + macro 状态守卫重放）、`macos-harness`（控真机）、`harness-anything`（Win COM 操控 Office/PS）、`loopx`（长任务状态内核）等能力后端拼装。任务状态机 `needs_software→needs_account→ready→running→needs_confirmation→done/partial/blocked` 每步可恢复。这是 34 家里几乎没有的「把一句话变成可打开/可操作/可部署唯一主成品」的最后一公里。

**⑦ 交付判据「短≠空」。** `_is_delivered` 是军团的交付判据底线：绝不拿长度当判据（合法短答「2」「好」就是真交付），只把占位词（UNKNOWN/NONE/N/A/null/未完成/无）判为「明确的无内容声明」触发熔断。这是对「用测试数/文件数冒充进展」的系统性抵抗，也是军团可靠性（杀前落盘、收尾预算隔离、空答案熔断）里最贴近用户结果的一条。

**异化的本质（一句话收束）**：34 家里，codex/deepseek/hermes/penguin 都在「把单个 agent 做深」——短循环、插件化、学习环、自进化；而军团回答的是另一个问题——**当世界已经有一群最强 harness，如何让它们为一个用户的意图协同工作、且用户不用知道复杂**。所以军团的每个机制（交接事实图、验证即搜索、置信级联、经验飞轮、真机设备层、短≠空）都是「群体协作与交付可靠性」的增量，而非「再优化一个单 agent」。这条定位来自产品之魂三内核（群体互相进化 / 最强全部为我用 / 智能远超单家），是它让军团区别于任何一家 harness，也让「超越最强单家」从口号变成要用真用户旅程反复验证的硬约束。

**诚实说我们没有的：** dsh 的插件生态广度与「零特权内核」的可组合性是军团目前不及的（军团的 adapters 是手写接入，不是声明式插件树）；codex 的短循环极简让单题直答速度上军团要多一层编排成本；hermes 的用户长期画像（Honcho 辩证建模）比军团的经验飞轮更深。我们承认这些差距，并把 dsh/codex 的架构点（WorldState 分段 + render_diff + 比例压缩）吸收为军团已验证的正向杠杆，而不是宣称全面超越。

### 5. 面试问答：10 个速答卡

1. **「你和 Codex 有什么区别？」** Codex 是单家极简短循环，靠 final schema 直答最快；我们是让 Codex 和其它最强 harness 并行/接力、并有跨家经验飞轮和补位兜底的运行系统，不替它们解题。

1. **「你和 DeepSeek Harness(dsh) 区别？」** dsh 是把一个 agent 的内部做成可组合插件树；我们是把「不同 agent」串成可编排军团。dsh 解决单家可扩展，我们解决多家协作与交付可靠性。

1. **「你和 Hermes 区别？」** Hermes 是单 agent 内置学习循环；我们把学习循环做成跨家共享——codex 答的题 cc 下次能召回，且按用户隔离。

1. **「你和 Penguin 区别？」** Penguin 是「一句话造一个自进化 agent」；我们是「一句话让一群最强 harness 一起交付一个作品」，自进化体现在群体经验与交付知识库，而非单个 agent 迭代。

1. **「你和 LangChain/LangGraph 区别？」** 它们是让开发者手搓 agent 的框架；我们是「运行系统 + 事实底座」，不写答题逻辑，只补上下文/工具/失败回流/完成契约。

1. **「你比最强的单家强在哪？」** 不靠融合/投票（已证伪）。唯一实测超单家的是置信级联：主答失败才升级，否则不加门丢答案。我们诚实——没证明的编排机制就保留单家。

1. **「你的自进化是什么？」** 不是 benchmark 迭代模型权重，而是经验飞轮：成功交付落库 → 相似题召回 → 采纳提置信度 → 淘汰无效经验，让群体从上次终点起步。

1. **「你怎么保证交付不是空的？」** 「短≠空」判据：合法短答是真交付，只熔断占位词（UNKNOWN/无）；外加杀前落盘、补位接力、占位词熔断三条可靠性底线。

# 军团-项目完整史

## 军团（legion-service 多 Agent 编排平台）项目完整史

> 面向面试准备的内部溯源文档。所有事实均标注源码 `file:line` 或学城文档 ID，宁缺毋滥，代码与日报里没有的结论不写。

### 一、立项背景

军团是 **2026 年 8 月 25 日** 从用户一句战略构想立项的（周报 2782703397）：

> 用 auto 做桌面控制，接入 codex、dsh、deepagent、hermes，增加 penguin/prime 自进化、cc 开源 agent——用户可自己切换、可自主控制标配列表，多个员工合理编排谁是底层，共享搜索、工具、skill。

它直接承接 auto 项目 8.22–8.24 的「六家对标」结论：那轮横评用真数据证明了**多家答案聚合、投票门控、topic 路由全部不敌最强单家**（auto 2/5 vs DeepSeek 3/5），并留下了两个关键输入——「保留独立推理路线再仲裁，不搞全家桶证据池」。军团不是再造一个答题器，而是把这些 harness 编成「给 C 端的 Agent 团队即服务」。

立项当天做了四件事定盘（周报 2782703397 §2.1）：①开源调研约 24 个项目（19/19 clone 均经源码核查，确认 fork omnigent 可省 2–3 个月）；②可行性总判——差异化定位「Agent-Team-as-a-Service」；③五条 ADR 架构决策；④统一签名 runner 接入 9 家 harness registry。

### 二、完整迭代时间线

#### 8.25（立项）

一句话构想 → 五条 ADR + 9 家 harness registry + 轻度调度器。**ADR-005 是本周最重要纠偏**：删除全部人写的能力表/荐人规则/固定流程，要不要 agent、几个、派谁、串/并行、是否复核、何时停，**全由 captain 模型自主决定**。真跑验证：给模型 harness_stats 后 3/3 稳定选出性价比最优的 deepseek。

#### 8.26（方法论实验，负结果定生死）

立项次日先用真数据回答「多家组队到底值不值」：**六种聚合架构（答案选择/约束核验/证据级聚合/分歧重搜/逐一反证/矩阵）+ 智能路由（topic/LLM 5-fold）全部实测失败**，均 ≤ 最强单家；**一致性门控被判死刑**（弱家一致时是「一起给同一个幻觉」，一致≠正确）。**唯一被真数据证明的 1+1>1 是置信级联 17→21/40**。

#### 8.27（上线 + 扩展批）

从「上线 Step1–Step13」（前后端打通→层级指挥→网关降级→交付物网页→cron→持续生成 session）到「军团扩展批 1–9」，git log 里是密集的 13 个 Step + 9 个扩展批，测试从 15/15 滚到 95/95、100/100。

#### 8.28（全量验证 DEPLOY_READY）

### 四、关键机制的原理（代码级）

**1. 自愈换模型（run_one）**
`run_one(key, task, qhash)`（`legion_core.py:3113`）是单家执行的兜底循环：首轮带 appid、失败真换模型/provider、方向归一、codex 错误回流、剥 think 草稿（commit `2402c88d`）。网关租约 `_GatewayLease`（`:1524`）按 cost_class 分级控并发，失败分类 `_build_failure_context`（`:2033`）区分「环境失败 vs 模型失败」。

**2. 跨家补位接力**
`_pick_relay_harness(failed_key, tried, valid)`（`:5022`）给失败的家选补位：可跑 + 本单没试过 + 不是自己，优先级 `_FAILOVER_ORDER = ["codex","cc","hermes","deepseek","jcode","penguin"]`（`:5019`）。一家用尽 attempt 仍失败 → task + 完整失败 context 转交另一家接力（带旧 context 不是失忆重跑）。

**3. 交付判据「短≠空」**
`_is_delivered(result)`（`:4945-4960`）只信 run_one 的客观结果，不在父层加语义/长度门——「合法短答案（如『2』）也是真交付」，删掉「至少 20 字」门。唯一例外是**事实门**：final 是占位词（UNKNOWN/NONE/N/A/null）不算交付。这条是 `_typed_outcome`（`:4963`）typed 单一事实源的基础，把「这单完成没有」从四处各自判断归一成 completed/partial/failed/incomplete/cancelled/blocked。

**4. 自主竞选首脑（elect_captain）**
`elect_captain`（`:429`）让平等成员基于同一现场自主竞选首脑，不固定某一家、不用父层关键词路由。选择器只比较提案的客观完整度（是否愿意、是否给可执行 tasks），**不评判业务答案、不融合答案**。候选顺序按本单方向实测重排（`:472-477`），显式候选/固定首脑仍完整尊重。

**5. 经验飞轮（context not control）**
`_record_experience`（`:9863`）把成功交付家的经验落进军团跨家记忆——「codex 这次答的，cc 下次 search 能看到」，且按 `user_id` 隔离（隐私，不串户）。`_recall_experience`（`:9905`）召回相似问题经验注入只读上下文，并给模型一个「adopted」回报入口让好经验置信度上升——**召回只是半环，只有 harness 自己知道用没用，父层绝不猜**。

**6. 置信级联（8.26 唯一被证明的增益）**
架构 = 最强主家 CC 执行 → 读取运行时可观测信号（search_count/elapsed/final_len/timeout，**不用 gold、不读题型关键词、不投票**）→ Logistic 级联决定是否升级。BC 40 题 17→21/40。这是军团「A/B 必须带来真性能提升」目标下少数有数据的正向机制。

**7. 派单池纯净性**
`_answer_keys_from_catalog`（`:316`）保证 capability/平台面家永不进答题池；任何 catalog 结果收集成 key 集合的派单消费点必须过它（回归锁 `tests/test_dispatch_pool_guards.py`）。

### 五、架构演进（几次重大跃迁）

1. **从「人写规则编排」到「全模型自主编排」（ADR-005）**：删掉 recommend/cost_tier/strong_on/_is_simple/pick_reviewer 全部硬编码，选择归模型。这是军团与 auto「context not control」一脉相承的哲学落地。
2. **从「聚合/投票求共识」到「保留独立路线 + 置信级联」**：8.26 六种聚合架构 + 一致性门控被真数据判死刑，确立「不融合、不投票、只并列呈现 + 运行时信号级联」。
3. **从「单次派活」到「DAG + 持续协调」**：`dispatch`（`:6248`）支持 Task DAG 多依赖分层并行（`_deps_satisfied` 三种依赖策略，`:4990`），并演进到首脑竞选的持续协调（持续首脑、原生上下文恢复）。
4. **从「能演示」到「敢交付」**：8.27–8.28 补位接力、完成契约三态、交付可靠性（杀前落盘/收尾预算隔离/空答案熔断）把「编排协议 done」升级为「用户真拿到交付物」。
5. **成员定位纠正**：8.28 把 cua/supervision/herdr/orca 从「harness」挪出成员池，归为能力后端（`legion_core.py:5-8`）——诚实分层，不虚报可用。

### 七、面试问答（深度追问预案）

**Q1：既然六种聚合架构和一致性门控都被你亲手证伪了，那军团「多 Agent 编排」的价值到底在哪？**
答：价值不在「事后融合答案」，在**编排 + 可靠性 + 自进化**三件事。①编排：ADR-005 让 captain 模型自主决定派谁、串并行、何时停，数据客观选择归模型（给 harness_stats 后 3/3 选出性价比最优的 deepseek）。②可靠性：单家用尽 attempt 仍失败 → 补位接力带失败 context，从 query 到交付 100% 不白卷。③自进化：经验飞轮让「codex 这次答的，cc 下次能看到」，好经验置信度上升、没人采纳的淘汰。我们明确守住了已证伪死路——不融合、不投票、不 topic 路由，只并列呈现 + 运行时信号级联（置信级联 17→21/40 是唯一被数据证明的 1+1>1）。

**Q2：**`**_is_delivered**`** 为什么要删掉「至少 20 字」的长度门？这和「防止交白卷」不矛盾吗？**
答：长度是「量」不是「质」。合法短答案「2」「好」就是完整交付，父层拿长度误杀会触发接力 = control，违反「给 context 不加 control」。所以只保留两个客观事实门：status=done 且 final 非空，且 final 不是占位词（UNKNOWN/NONE/N/A/null 是「我不知道」的明确无内容声明）。占位词过滤和「短≠空」不冲突：短答是内容，占位词是无内容声明（`legion_core.py:4946-4960`）。配套的 `_typed_outcome` 把 completed/partial/failed/incomplete 归一成一份结构化投影，而不是一个笼统布尔。

**Q3：经验飞轮为什么坚持「父层绝不猜用没用」？**
答：召回是半环，只有 harness 自己知道哪条经验真被采纳了。父层替它宣称「参考了/辅助了本次回答」是典型的「在 harness 上方另造质量裁判」，会造成上下文污染和假置信度。所以 `_recall_experience` 只注入「找到 N 条历史经验供参考」的事实，并给模型一个 `legion_tool.py adopted "<Q 原文>"` 的真回报入口——好经验靠真实采纳票浮上来，没人采纳的 prune 淘汰。这是「学习飞轮闭环」能转起来的关键：置信度来自真实运行反馈，不来自父层猜测。

# Pilot复盘-完整过程

## Pilot 复盘：外部监控层的完整过程

> 候选人：李璇。本文从代码 + git 历史 + 学城日报还原「Pilot」这一技术故事的完整过程，供面试深挖使用。
> 事实出处统一标注为「文档 ID」（学城日报）或「file:line」（仓库源码）。

### 一、背景与触发

Pilot 挂在 auto 项目（`seed-users-system/qa_system/`，一个 GAIA 上能做到 98% 的自主问答 agent）之上，是给 **Claude Code（CC）个人开发循环** 做的一层「外部监控层」。

它的原始假设一句话就能说清（文档 2782893592）：

> 「CC 会犯懒、跑偏、忘事 → 在外面挂一层监控（打脸记忆、目标追踪、回复自检、意图分析），每回合注入上下文，让 agent 越来越聪明」。

背景数据支撑：auto 在 GAIA 上已经 95%+/98%，说明「模型检索和推理能力本身没问题」；但李璇在 CC 里亲自做多轮开发时反复观察到三个现象——**改了代码没验证就想停、只查一半就下结论、光说要做没真做**。于是她把「智能提升」这件事押在了「在循环外面再挂一层 LLM 监控」上。

最终规模（文档 2782893592）：**62 个 py 文件 · 13,246 行代码 · 6 周生命周期 · 41 项 sanity check**。2026-08-24 从 `~/.claude/settings.json` 永久移除（备份 `settings.json.pilot-backup-20260824-163503`，哨兵 `/tmp/MEYO_HOOKS_DISABLED` 保护存量 session）。

### 二、完整时间线

- **2026-07-15 启动**：搭起 watchdog LLM，按层累加监控能力（文档 2782893592「2026-07-15 → 2026-08-24 停用」）。
- **2026-07-31 · load 418 事件**：一次 **fork bomb** —— 3 个 Stop hook 各自 spawn `claude --model haiku`，多 session × 每 turn × 多次 spawn，把机器 load 冲到 418。这次事故换来了 **spawn 纪律**（统一入口、进程闸门、哨兵、fail-safe 全静默），是 Pilot 少数真正的硬资产（文档 2782893592 三·1）。
- **2026-08-22 · 深度层回测 0/10**：唯一被真正测过的一层——「LLM 审 LLM 的回复」回测精度 **0/10，假设被证伪**，`pilot_stop.py` 已删（文档 2782893592 二）。
- **2026-08-24 · 停用**：把 Pilot 从 settings.json 永久移除。关键细节：**8-24 的哨兵关闭其实是基础层第一次真实测试——用户完全没注意到它消失了**（文档 2782893592 二「基础层」行）。
- **2026-08-27 · 重构为续航副驾**：把判断逻辑抽成纯内核 `pilot_kernel.py`（108 行），CC 个人 hook 和军团「持续到完成」按钮共用同一份判断；并彻底删掉 BC/GAIA 提分那一整套（`dev/pilot-charter-system.md:16-20`、`dev/pilot-refactor-plan.md:5-9`）。

### 三、技术细节（代码级）

Pilot 按功能分成四块（文档 2782893592 二）：

| 层 | 设计 | 实现要点 |
| --- | --- | --- |
| **深度层**（cognitive / introspect / judge_before_stop） | LLM 审 LLM 的回复 | 用第二模型逐回合评判主模型回复质量 |
| **基础层**（tag / feedback / learner / goal / working_memory 等 8 个注入） | 规则注入提醒 | 纯正则/规则，从不调模型 |
| **目标追踪**（goal_tracker） | 距离目标注入 | v1.0 的「距离 100%」文案直接引发 CC 无限循环（"Goal not yet met… continuing"），重写成 v1.2 指令式 |
| **跨 session 汇报**（daily report） | 可见性 | 有边际价值但不在关键路径 |

**停用前的代码现状**（`dev/pilot-refactor-plan.md:8-10`，李璇自己量出来的）：`pilot_v2.py` **771 行 / 28 函数 / 15 正则**，其中 `stop()` 一个函数就 143 行；提分残留约 54 行（`score_gate`/`_read_score`/`_score_status`/`_SCORE_GOAL`/`no_gain`）——这些都是军团时代前为刷 BC/GAIA 分数而写的纯负担。

**重构后的形态**（`dev/pilot-refactor-plan.md:15-26`、`tools/pilot_v2/pilot_v2.py`）：

```Python
// 代码块
pilot_kernel.py   # 新·纯续航内核(无IO、无hook、可被任何人import)
  decide(reply, state, config) -> {"action":"continue"/"stop", ...}
  # 就一个纯函数:给它"上一句回复+状态+用户配置",返回该不该继续。
pilot_v2.py       # 瘦身后·只做"hook 胶水"(我个人用)
```

hook 胶水现在只挂四个入口（`tools/pilot_v2/pilot_v2.py:510-519`）：`session-start` / `user-prompt` / `post-tool` / `stop`。核心的假停顿识别是四条正则判据（`pilot_v2.py:38-41`）：未完成信号 `_EXPLICIT_INCOMPLETE`、完成声明 `_DONE`、测试工具 `_TEST_TOOL`、失败信号 `_FAILURE`。stop 时的放行逻辑是「**倾向继续三问**」：①目标达成没？②说到做到没？③有动作没进展没（grep/Read 完就停）——任一没过就 block（`dev/pilot-charter-system.md:97`）。

### 四、完整反思过程（假设 → 验证 → 推翻 → 再假设）

1. **初始假设**：外面挂一层 LLM 监控，每回合注入上下文，能让 agent 越来越聪明。
2. **第一轮验证（深度层）**：2026-08-22 对深度层做回测，精度 **0/10**——「LLM 站在旁边看 LLM 干活」根本判不准。**假设被直接证伪**，`pilot_stop.py` 删除（文档 2782893592 二）。
3. **对基础层的诚实审计**：李璇发现 `PILOT_STATUS.md` 里写的「基础层全都有效」**混淆了「在跑」和「有用」**——基础层 8 个注入**从未做过任何 A/B 或回测**。而 8-24 的哨兵关闭，意外成了它的第一次真实测试：**用户完全没注意到它消失了**（文档 2782893592 二）。
4. **重新归因**：把「监控层能提升 agent」这个总假设，拆成「深度层（LLM 审 LLM）」和「基础层（规则注入）」分别验收后，结论清晰了——深度层被证伪，基础层没证据，goal_tracker 还没证明自己就被停用了。
5. **收敛到一条深层规律**：同一套思想（目标逼近、验证即行为、打脸记忆），放在**循环内部**（`qa_system` 的 `goal_approach` / `verify_as_search`）被 GAIA 回测、bc-attack 真跑、对照实验验证过、被外部评审（Autodo 适配性报告）列为「值得拿走」；挂在**循环外部**（memory_gates 的 pilot hooks）长期无测试，直到被证伪后亲手停用（文档 2782893592 四）。

### 五、最终结论与教训

结论一句话（文档 2782893592 标题与五）：

> **Pilot 作为产品失败了，作为实验成功了**——它花六周证明了「外部监控层提升 agent」这条路不通，顺手留下了一套 spawn 纪律和一条选址原则：**智能要长在循环里面，不是挂在循环外面**。

净账本（文档 2782893592 三）：

- **真实收益**：①7-31 load 418 换来的 **spawn 纪律**（停用当天用的正是它自己建的哨兵）；②**证伪本身就是产出**——保证以后不再花六周重走这条路；③一批可迁移的 hook 工程知识（`stop_hook_active` 重入防护、stdout 即 additionalContext 的坑、goal 评估的 token 成本模型）。
- **真实成本**：load 418 一次；停用前 2 天 3 次打断开发的 continuation 事故；**每回合尾部 12-25s 隐形税**（停用当天才量化出来）；每次 goal 评估 10-25s × xhigh reasoning；持续维护债（41 项 sanity check、CLAUDE.md 追着代码改总落后）。

三条带走即用的原则（文档 2782893592 五）：

1. **外部监控层（watchdog LLM）提升 agent 这条路已证伪**——精度 0/10，别再走。
2. **spawn 纪律**（统一入口 + 闸门 + 哨兵 + fail-safe 静默）是所有 hook 体系的生死线。
3. **智能要长在循环里面，不是挂在循环外面**——适配性评审夸的那批机制（verify_as_search 等）恰恰就是长在里面的那批。

Pilot 的遗产不是那些 hook 代码，而是这三条原则。它后来演化为两个新形态：个人侧的 **Pilot v2 续航副驾**（`tools/pilot_v2/`，git 历史 `5c1fcd97`、`c8cd740e`）和军团侧的 **「持续到完成」按钮**（共享同一份 `pilot_kernel.py` 纯内核）。

### 六、面试回答脚本

#### 3 分钟版

> Pilot 是我做的外部监控层——一个 watchdog LLM 挂在 Agent 循环外面监控质量。6 周、62 个文件、1.3 万行、41 项检查。它最初的假设是"CC 会犯懒跑偏，我在外面挂一层监控，每回合注入上下文，让它越来越聪明"。

> 然后我做了逐层验收：深度层——LLM 审 LLM 的回复——回测精度 0/10，假设被证伪；基础层 8 个规则注入，我发现它从来没做过 A/B。最刺痛的是 8 月 24 号我关掉哨兵，用户完全没注意到它消失过。

> 但我不认为这六周浪费了。它换来了三样东西：一次 load 418 的 fork bomb 事故逼出了 spawn 纪律；证伪本身是产出，保证以后不再重走这条路；还有一条选址原则——同一套思想放在循环内部（verify_as_search/goal_approach）被外部评审列为"值得拿走"，挂在循环外部的被我亲手停用。

> 结论一句话：**智能要长在循环里面，不是挂在循环外面**。这个决策让我建立了自己的判断标准：一个机制有没有价值，看它在循环内的增益，不看它文档里的自述。

#### 追问应对

- **「你为什么不做 A/B 就上线？」** → 诚实承认：基础层确实没做 A/B，这是当时的方法论缺口。PILOT_STATUS.md 里写的"有效"混淆了"在跑"和"有用"，我是停用当天才真正量化出"每回合 12-25s 隐形税"。这直接催生了我后来的习惯——**机制必须进回归测试，监控层自己不进测试就永远在制造新故障模式**。
- **「外部监控完全没用吗？」** → 不是。有用的是 **spawn 纪律**（统一入口/闸门/哨兵/fail-safe 静默），那是 load 418 事故换来的硬资产，停用当天用的正是它自己建的哨兵。证伪的是"LLM 站旁边看 LLM 干活"这一条。
- **「那 Pilot 后来怎么了？」** → 拆成两块：个人侧重写为 Pilot v2 续航副驾（纯函数内核 `pilot_kernel.decide()`，108 行），军团侧变成"持续到完成"按钮，两边共用同一份判断内核。本质是从"外部监控"退回到"续航控制"，只做"该不该继续"这一个窄问题，不再试图替 agent 判断质量。
- **「这和 context not control 什么关系？」** → 同一件事的两面。Pilot 的失败是我亲手验证了"control 挂在外面"不 work；教训是让判断**长进循环里**（context），而不是在循环外再叠一个控制层。

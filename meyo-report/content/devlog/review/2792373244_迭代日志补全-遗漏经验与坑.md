### 二、新发现的经验与坑（≥10 条，现象→根因→结论→出处）

#### 坑 1：交付面错位——"完美地错"（R0，最上游）

- **现象**：B站投稿包 9 任务全 done、独立复验通过，但用户说"都不是视频"，投稿包只有封面/文案/配音。
- **根因**：`north_star.job` 写着"直接上传"，但 `required_artifacts` 只有图/文/音三类；验证/研究/首脑没有任何一层反问"该平台发布唯一不可缺的是什么"。意图反推层缺口。
- **结论**：修好下游 R1-R10 仍会在错误的交付面上做到完美。通用解法是 `core_medium` 结构化——对"包/发布/投稿"类订单先反推平台发布入口与最终消费形态，字面清单缺核心媒介时补齐或向用户确认。
- **出处**：【`2786071729`→`2786241556`/`2786122005`】

#### 坑 2：研究"完成"是文本状态，占位句也能 done（R1）

- **现象**：anchor5b 研究 292 秒标 done，final 只有"现在我将编译完整的 LEGION_FRONTIER_CONTEXT JSON 输出："占位句，0 artifact。
- **根因**：`project_context.py:220-233` 协议解析失败静默返回空；仅 Markdown 链接也算研究完成。
- **结论**：研究完成门必须是协议完整性（解析成功 + anchors 非空 + 至少一个桂冠锚 + URL 可回访），失败改 incomplete/revise 禁止 done。
- **出处**：【`2786453793`/`2786241556`】

#### 坑 3：正确的锚点文件存在，但没进控制面（R2/R3/R4）

- **现象**：anchor5 的 `concept_anchors.json` 九维桂冠锚全部正确，但 packet `concept_anchors=0` 条；五条 trace 根 `quality_context` 均为 0 anchors。
- **根因**：①`project_context.py:343-354` 只解析 final 协议块不读 artifact；②`record_concept_anchors()` API 存在但无调用方；③锚点持久化 schema 只留 5 字段（acceptance/lineage 丢失）；④**零锚点时 crown complete gate 是 fail-open**——`legion_core.py:4577-4584` 只有非空 crown rows 才拦，"缺标准反而免检"。
- **结论**：这是"正确研究已存在仍未成为共享事实"的经典案例；artifact 是数据面不是控制面。零锚必须 fail-closed。
- **出处**：【`2786453793`/`2786261246`/`2786111695`】

#### 坑 4：坏 owner 可进入持久执行图，11 次 reopen 0 attempt（R5/R6）

- **现象**：anchor5b 的 `direction_review.assigned_harness="direction_review"`（逻辑节点名当执行者）永远 pending；首脑新增 5 任务 + 11 次 reopen 全部 attempt 0。
- **根因**：`team_state.py:225-238` `assigned_harness` 回退 key，逻辑节点名可成为成员名（Codex 定位的生成点）；`reopen 只重置状态`，不是 dispatch。
- **结论**：入图前必须统一强绑定（task_id 自绑定自动重绑或 blocked），continue 后每个开放节点一轮内必须出现 `queued/attempt_started/blocked_with_reason` 之一。
- **出处**：【`2786181808`/`2786453793`】

#### 坑 5：done 不要求效果证据，将来时承诺冒充完成（R7）

- **现象**：web150d 的 `revision_1_deepseek` 只输出"我会先核对…"计划句、0 artifact、5.2 秒，被标 done；`"现在我将…"` 式占位修订反复被当候选。
- **根因**：`team_state.py:447-475` 信任返回的 status，不检查 artifact/diff hash/复测。
- **结论**：done 必须按 task_kind 绑定效果证据——将来时承诺、0 artifact、无 diff 一律 incomplete。这是"交付判据短≠空"的姊妹坑：**计划句≠完成，不只是短答案误判**。
- **出处**：【`2786453793`/`2786241556`】

#### 坑 6：机器 PASS ≠ 世界级 PASS（R9）

- **现象**：goal18 机器审计 8/8 PASS，但三轮独立审查持续 REVISE/BELOW_FRONTIER；20 次 resume_claimed 高活动低产出。
- **根因**：真人专业审校、新手测试、独立盲评没有在计划阶段建成可执行任务。
- **结论**：真人证据必须一级资源化；不可得时立即封 claim ceiling 为 BELOW_FRONTIER 并停止机器空转。**系统能发现缺口，但没有把真人/盲评证据作为必须完成的发布依赖。**
- **出处**：【`2786181808`/`2786453793`】

#### 坑 7：环境代理坑——rc1 先查代理活没活，别当模型限流

- **现象**：HTTP_PROXY 指向没起的代理 → 军团起子进程继承死代理 → 全家 rc1。
- **根因**：子进程继承父进程环境变量。
- **结论**：军团 rc1 先查环境代理活没活；这解释了后续"子进程传 NO_PROXY"铁律的由来。
- **出处**：【`2783607085`】

#### 坑 8：并发效率没接管——整层等待吃掉并行收益

- **现象**：3 家显式并发单家约 13s、总耗时 54.7s 接近串行；后来 py-spy 揪出 `singleflight 锁` 把 6 家并发 60s TIMEOUT 拉到 14s。
- **根因**：`_dependency_waves` 先把任务分层、等整层清空才走下一层；`event_driven` 分支只让失败任务尽早接力，成功任务的后继仍被整层边界挡住。确定性示例：A(2单位)→C(4单位) 与 B(10单位)，当前分层 `[[A,B],[C]]` 总 14，依赖就绪应总 10。
- **结论**：**事件驱动补位 ≠ 事件驱动依赖调度**；单家并发物理开销（auto/deepseek 40-50s 是 harness 本身重）与父层链路是两个问题，慢在哪要分开测。
- **出处**：【`2783607085`/`2784491892`/`2785928871`】

#### 坑 9：DOMTokenList 空 token 中断整条 JS 链，造成"连不上服务"假象

- **现象**：军团跑起来、有家 fail 时，顶部"连不上服务"、所有面板"Failed to fetch"，后端 API 实际健康（HTTP 200）。
- **根因**：`web/index_v2.html:1164` `lane.classList.add(cls==='done'?'done':'')`——家 fail 时 `add('')` 空字符串抛 `DOMTokenList` 异常，中断 JS 执行链。
- **结论**：前端"连不上服务"未必是后端挂了，先查前端 JS 异常链；全局兜底 + 单个面板失败不连累全局。
- **出处**：【`2783606835`】

#### 坑 10：盲评评委点名的交付保障缺口（P0 级高频）

- **现象**：候选零产物进评审、成品路径写成占位符"本方案"用户找不到文件、不存在的图片不标红、可双击网页无证据。
- **根因**：交付保障没进编排层——缺"产物落盘校验 + 失败自动上报 + 真实路径声明 + 交付扫描自动验证文件存在/可打开 + 可双击网页附截图/录屏/验证报告"。
- **结论**：这些是编排层可直接补的通用能力，不是 harness 自主范畴。
- **出处**：【`2783935355`】

#### 坑 11：接入体检/工具体检"假通过"（A05/A14）

- **现象**：接入工具体检在磁盘没有文件时，仅 final 含标记也能通过（`passed=true 且 target_exists=false`）；工具提供者清单为新成员缺声明时填默认 `shell/read/write/search/web` 并宣称 available。
- **根因**：体检以模型自报标记为准，不以实际文件与精确内容读回为证；默认清单冒充真实工具能力。
- **结论**：区分声明/探测/真调用，"体检绿"不代表"工具可用"，要实际文件读回 + 真调用为证。
- **出处**：【`2786641463`】

#### 坑 12：模型健康归因错位 + 批次分配降档（A06/A12）

- **现象**：模型健康成功记在**请求模型**而不是 adapter 返回的**实际模型**；批次分配为取得不同 appid 会选较弱模型，即便强模型可复用。
- **根因**：请求/实际/未知三者未分开记录；容量分流与质量取舍未显式化。
- **结论**：健康与费用只按可信实际事件归因；比较军团收益必须计入真实成员模型差异。
- **出处**：【`2786641463`】

#### 坑 13：记忆/知识/搜索 8 项只读审计问题（9.12 专项）

- **召回整库回写丢更新**：A 召回读旧库、B 追加新经验、A 用旧快照覆盖全库，B 的经验消失（`legion_memory.py:222-233`）——原子 rename 只防半份文件不防丢更新。

### 三、新案例与效果解释

#### 案例 1：群体 vs 个体竞技场——统一规律（8.30）

4 类交付盲评（首脑扩编≥10人编排 → 群体 dispatch vs 10 家个体独立 → 匿名脱敏 → 未参与评委盲评）：cc 反常识简答群体 85.8 vs 个体 84.9（微胜）；codex 写代码群体 **83.5 vs 63.0（大胜翻盘）**；hermes 深研三件套 63.5 vs 74.0（cc 能独扛，势均）；ironclaw 图片视频 82.0 vs 87.0（势均）。**规律：单家扛不动则群体碾压，单家能独扛则群体是"更稳非更强"**——这是"群体编排"最诚实的一次效果解释，比"永远赢"口号更有说服力【`2783607085`/`2783247069`】。

#### 案例 2：速度攻坚的真实数字链（9.1）
